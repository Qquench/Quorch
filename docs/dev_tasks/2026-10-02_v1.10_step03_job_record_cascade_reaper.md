#### 【缺陷根因与修改目标】
```
【根因分析】
1. 当前 jobs/ 路径下的 .record.json 与 .result.json 缺乏自动生命周期收敛机制，导致 session 子目录与小文件无界膨胀，compute_protected_logs 每轮 submit 的目录遍历面临潜在的 O(N^2) 退化风险；
2. 现有 gc_terminal_jobs 包含 os.stat mtime 调用，既破坏了 Zero-stat 契约，又属于未接入运行链路的测试死代码；且 job_id=uuid4 缺乏时序原语；
3. 量级与身份级错配隐患（Critical-1）：若 Phase 2 调用 enforce_unified_log_quota 时未透传与记录窗口同源的 protected_paths，日志目录内的 consult 等非作业日志将导致名序计数与记录窗口错位，误删 40 条保护锚对应的底层日志；
4. 双源计算漂移（Critical-3）：若 collect_terminal_records_ordered 与 compute_protected_logs 各自独立实现窗口，排序键与边界极易发散；
5. 快照异源与 TOCTOU（High-2）：Phase 1 收集与 Phase 2 删除若非同一临界区，并发 submit 插入新任务会导致有序窗口偏移，删除错误边界的记录。

【修改目标】
1. 统一日志与记录保留量级，声明 REVIEWER_RECORD_RETENTION: Final[int] = 40，显式校验断言 REVIEWER_RECORD_RETENTION == REVIEWER_TERMINAL_LOG_RETENTION (40) > REVIEWER_LOG_QUOTA_KEEP (20)（防 python -O 剥离）；
2. 确立以 (log_basename, session_id, log_path, record_path) 字典序（等价时间序）为唯一主轴排序键，compute_protected_logs 统一委托 collect_terminal_records_ordered 派生，实现保护集单一真源；
3. 实现两阶段单临界区级联回收：在同一 filelock 保护下，基于单次 listdir 快照驱动日志修剪（显式传入 keep=40、registry 与同源 protected_paths）与记录回收，确保记录绝不先于其受保护日志被删；
4. 孤儿记录判定基于「快照集合 − 本轮 logs_reaped」差集重算并直接回收，杜绝无界滞留；活锁逃生强制双重比对 owner_pid 与 owner_boot_nonce（boot_nonce 不匹配优先判死）；
5. rmdir 空 session 目录吞并 ENOTEMPTY/ENOENT/EACCES；poll 路径针对 record/result/log 的缺失统一降级为 record_pruned / log_pruned，严禁抛出未捕获的 FileNotFoundError。
```

#### 【分步改造指引】
1. 在 log_naming.py 声明 REVIEWER_RECORD_RETENTION = 40，使用显式 `if not (...) raise AssertionError(...)` 校验 `RECORD_RETENTION == TERMINAL_LOG_RETENTION > LOG_QUOTA_KEEP`；抽取按 `(log_basename, session_id, log_path, record_path)` 升序排序的纯函数。
2. 重构 compute_protected_logs：内部委托 collect_terminal_records_ordered 提取有序终态记录的 log_path，消除双源漂移。
3. 在 reviewer_jobs.py 将 gc_terminal_jobs 改写为单临界区级联回收：在 filelock 内执行单次 listdir 快照扫描，Phase 1 纯计算窗口外超期记录；Phase 2 先调用 `enforce_unified_log_quota(..., keep=REVIEWER_TERMINAL_LOG_RETENTION, registry=registry, protected_paths=compute_protected_logs(jobs_root))` 清理窗口外日志（计入 logs_reaped），随后成对回收超出 retention 窗口的终态记录（计入 records_reaped）。
4. 孤儿记录差集回收：对 `orphan_set = snapshot_logs − logs_reaped_this_round` 之外（即磁盘上对应 log_path 已缺失）的终态记录，无条件回收其 .record.json 与 .result.json（计入 orphans_reaped），杜绝无界滞留。
5. 强化活锁逃生机制：对非终态作业，同时比对 owner_pid 与 owner_boot_nonce（boot_nonce 不匹配优先判死）；确证死亡者由 CAS 迁为 ORPHANED 终态（计入 orphans_rescued）。
6. 目录收割与异常容错：rmdir 空 session 目录时捕获 ENOTEMPTY、ENOENT、EACCES 静默吞并，防止并发原子写入打断整轮回收。
7. 挂接调度与节流保护：在 ReviewerJobSupervisor 的 reconcile_on_load 中执行全量对账清理，在日常 submit 路径上设置节流阈值（如每 10 次 submit 执行一次轻量回收，带单飞互斥与 acquire 超时跳过）。
8. poll 全路径降级保护：poll 及日志读取在面对缺失的 .record.json / .result.json / .log 时，统一优雅返回 record_pruned / log_pruned 状态，绝不向上抛出 FileNotFoundError。
9. 编写 test_job_record_cascade_gc.py 单测，断言 identity 级保护（存活记录对应日志必存活）、日志先行时序、(log_basename, session_id) 排序确定性、单一真源派生、孤儿记录零滞留、boot_nonce 校验及 python -O 自验命令。

#### 【防御与边缘校验】
- 保护锚不变量：前 40 条终态记录绝不先于其对应的 .log 日志被删除；Phase 2 必须显式传参 `keep=REVIEWER_TERMINAL_LOG_RETENTION` 与同源 `protected_paths`，严格保证保护集优先级高于计数修剪。
- 排序主轴单调性：必须以 log_basename 为绝对第一排序主键，消除 session_id 随机 UUID 对时序的扰动；latest-* 及非规范名显式排除或稳定序兜底。
- 单临界区快照与死锁防范：filelock 必须完整覆盖「快照获取 -> 纯计算 -> 日志清理 -> 记录删除」全链路，enforce_unified_log_quota 内部严禁二次 acquire 同一 filelock 造成自死锁。
- 孤儿记录清理使用清理后差集：严禁使用清理前快照原始存在性，避免单轮零滞留假闭合。
- Zero-stat 红线：回收路径严格遵循 Zero-stat 契约，仅允许 os.listdir 与 unlink/rmdir，严禁调用 os.stat、os.lstat、os.path.exists。
- 活锁逃生双重校验：必须同时比对 owner_pid 与 owner_boot_nonce，防范 PID 复用误杀或滞留。
- 悬挂指针优雅降级：poll 或读取接口对已被 GC 淘汰的记录或日志返回 record_pruned / log_pruned，严禁抛出未捕获 FileNotFoundError。
- 显式 raise 红线：所有模块加载期核心不变式统一使用显式 raise 抛出，杜绝在 python -O 优化模式下被静默剥离。
