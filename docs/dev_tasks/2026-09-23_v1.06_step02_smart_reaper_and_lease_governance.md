> **粒度守卫说明**: 核心受管生产代码仅 2 个（`manifest.py`, `server.py`），严格满足 $\le 3$ 核心生产文件门禁；测试代码（`test_heartbeat_renewal.py`）豁免核心计数。

#### 【缺陷根因与修改目标】
- **根因 1（心跳源缺失）**：`TaskRecord.last_heartbeat_*` 仅在 `commit_lease`/`compare_and_swap`/`release_lease` 单次事件时刷新；长任务执行期间无任何周期性刷新通路，"心跳静默"判据对所有合法长任务恒为真，回收器将失去判别力。
- **根因 2（跨进程时钟失真）**：`last_heartbeat_monotonic_ns` 为进程内单调时钟，跨进程不可比；`last_heartbeat_wall_utc` 可跨进程但受 NTP 回拨影响，可能产生负时长。
- **修改目标**：在 `manifest.py` 增量引入 `touch_heartbeat`（代际/token 双校验原子更新）；在 `server.py` 注册 FastMCP 原生工具 `dev_tasks_heartbeat`（支持外部周期性探活）并在核心工具调用前置拦截器中自动刷新活跃任务心跳。

#### 【目标签名与类型契约】

#### 【分步改造指引】
1. **`manifest.py::touch_heartbeat`**：在 manifest 文件锁临界区内加载清单，定位目标 `task_id`，校验 `record.generation == generation` 且 `record.holder_token == holder_token` 且 `record.released is False`；更新 `last_heartbeat_wall_utc` 与 `last_heartbeat_monotonic_ns`，调用 `atomic_replace_manifest` 安全落盘；校验不匹配立即返回 `False`。
2. **`server.py::dev_tasks_heartbeat`**：实现 FastMCP 工具，支持显式传递 `task_id` 与 `holder_token`，或在未传时自动读取当前活跃任务；调用 `touch_heartbeat` 并返回结构化状态 `{status: "ok" | "rejected", task_id: ..., generation: ...}`。
3. **零空写与零 Stdout 污染**：心跳逻辑严禁使用 `print()`，所有日志走 `RotatingFileSink` / 审计通道，保证 JSON-RPC 帧 100% 洁净。
4. **单测覆盖**：新建 `test_heartbeat_renewal.py`，验证合法续约、陈旧代际被拒、已释放任务续约被拒、以及并发心跳调用下的原子性。

#### 【防御与边缘校验】
- **负时长夹逼**：`heartbeat_silence_seconds` 计算使用 `max(0.0, ...)`，防止 NTP 回拨触发次生误判。
- **代际 × token 双校验**：`touch_heartbeat` 必须双验证，防已回收的旧持有者"续命"。
- **并发写入原子性**：心跳刷新严格受 `FileLock` 保护并通过 `atomic_replace_manifest`（原子替换）写盘，绝不损坏清单。
- **零破坏兼容**：旧版本未带心跳的租约记录自动平滑解析为初始状态，反序列化绝不抛栈。

#### 【缺陷根因与修改目标】
- **根因 1（单一绝对超时误杀）**：仅凭单一固定超时无法区分“深度思考/复杂单测执行中的健康长任务”与“子代理崩溃断线遗留的死锁僵尸”。
- **根因 2（只读任务活性代理失效）**：纯审查类/只读类长任务不改动工作区，`[Affected Files]` 的 mtime 恒陈旧；若仅依赖 mtime 会把健康的 Reviewer 误杀。
- **修改目标**：新建 `reaper.py` 实现 `probe_lease_health` 多维健康判定引擎；在 `project_config.py` 扩充 `reaper_policy` 配置域；核心逻辑遵循“心跳新鲜度对 mtime 陈旧具有绝对否决权（强活性信号）”，输出三态健康裁决（`HEALTHY`, `STALE_SUSPECT`, `RELEASED`）。

#### 【目标签名与类型契约】

```python
# plugins/quench-dev-tasks/server/reaper.py
from dataclasses import dataclass
from enum import Enum
from typing import Optional, Tuple

class HealthVerdict(str, Enum):
    HEALTHY        = "HEALTHY"
    STALE_SUSPECT  = "STALE_SUSPECT"
    RELEASED       = "RELEASED"
    NO_LEASE       = "NO_LEASE"

@dataclass(frozen=True)
class ProbeEvidence:
    task_id: str
    verdict: HealthVerdict
    heartbeat_silence_seconds: float                         # 负值强制夹为 0.0
    affected_files_max_mtime_age_seconds: Optional[float]    # None = 无文件范围，mtime 维度缺席
    holder_token: str
    generation: int
    reasons: Tuple[str, ...]                                 # 结构化判定理由，便于 CLI 渲染

def probe_lease_health(
    workspace_root: str,
    *,
    task_id: str,
    heartbeat_silence_threshold_seconds: float = 900.0,
    affected_files_mtime_threshold_seconds: float = 600.0,
) -> ProbeEvidence:
    """对指定任务的活跃租约进行多维只读健康度探测。"""
    ...
```

#### 【分步改造指引】
1. **`reaper.py::probe_lease_health`**：只读模式加载 `manifest.json`，提取活跃租约；计算心跳静默时间差（`max(0.0, wall_clock_diff)`）；遍历任务单声明的 `[Affected Files]`，统计受管文件的最大 mtime 距当前时长；综合判定：
   - 若租约已释放或不存在，返回 `RELEASED` / `NO_LEASE`；
   - 若心跳在阈值内，**无条件判定 `HEALTHY`**（即便 mtime 陈旧）；
   - 若心跳超时且受管文件 mtime 超过阈值（或无文件变更），判定为 `STALE_SUSPECT`。
2. **`project_config.py`**：扩展 `ReaperPolicyConfig`，包含 `heartbeat_silence_threshold_seconds` (默认 900) 与 `affected_files_mtime_threshold_seconds` (默认 600)，接入 `_coerce_positive_int` 安全校验。
3. **单测覆盖**：在 `test_reaper.py` 中覆盖心跳新鲜+文件陈旧（健康）、心跳陈旧+文件新鲜（健康）、双陈旧（可疑）、无文件范围任务的降级处理。

#### 【防御与边缘校验】
- **合取降级不变量**：mtime 维度缺席时必须显式标注降级原因，绝不允许“静默丢弃维度”造成僵尸任务无法回收。
- **性能护栏**：`probe_lease_health` 必须为常数次磁盘读（仅 manifest 一次 + 每个受管文件一次 `stat`），不引入任何 O(N) 全盘扫描。
- **只读纯洁性**：探针函数保证 100% 只读，严禁在探针内部产生任何文件写入或锁竞争。

#### 【缺陷根因与修改目标】
- **根因 1（僵尸死锁无安全解法）**：当子代理崩溃后，任务单停留在 `[In Progress]` 状态，全局排他锁导致全仓开发停滞；人工编辑文件容易绕过代际造成双写冲突。
- **根因 2（回收竞态与 TOCTOU）**：若在探针检查与执行回收之间目标任务恢复并完成，盲目强制回收将破坏正常交付产物。
- **修改目标**：在 `reaper.py` 实现 `reclaim_stale_task`（基于预期 generation 的原子 CAS 判定与回收）；在 `state_machine.py` 补充回收状态流转支持；在 `server.py` 注册 `dev_tasks_reclaim` MCP 工具，要求携带证据或强制确认，CAS 成功后递增 generation 彻底作废旧持有者令牌。

#### 【目标签名与类型契约】
```python

def reclaim_stale_task(
```

#### 【分步改造指引】
1. **`reaper.py::reclaim_stale_task`**：在 `manifest.json` 文件锁临界区内复核探针；校验 `expected_generation`；CAS 成功后调用 `release_lease` 递增 `generation`；更新任务单 markdown 状态由 `[In Progress]` 回退至 `[Confirmed]`。
2. **`server.py::dev_tasks_reclaim`**：注册 FastMCP 工具，参数包含 `task_id`、`expected_generation`、`expected_holder_token`、`force`，返回结构化回收结果与审计追踪信息。
3. **`state_machine.py`**：支持安全的回收状态流转回退路径（`In Progress → Confirmed`），同步更新状态机内存与任务文件。
4. **单测覆盖**：在 `test_reclaim_cas.py` 中测试正常回收、健康任务被拒回收、陈旧代际幂等返回、并发争抢回收。

#### 【防御与边缘校验】
- **锁内重探防 TOCTOU**：`reclaim_stale_task` 必须在 manifest 文件锁内重新执行健康探针判定，拒绝信任调用方传入的历史陈旧证据。
- **幂等回收语义**：`generation != expected_generation` 或 `released is True` 时返回幂等成功，绝不报错中断。
- **旧令牌彻底失效**：回收必须单调递增 `generation`，被回收的子代理即便复活，后续的任何提交和心跳均会被 fail-closed 拒认。
