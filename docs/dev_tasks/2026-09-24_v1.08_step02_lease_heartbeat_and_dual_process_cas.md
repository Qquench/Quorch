#### 【涉及文件】
```
[MODIFY] plugins/quench-dev-tasks/server/manifest.py
[NEW] plugins/quench-dev-tasks/server/tests/test_dual_process_cas.py
```

#### 【缺陷根因与修改目标】
```
【根因分析】
在双宿主架构中，Reviewer 进程与 Runner 进程各自以独立的 stdio 启动 server.py。若进程直接依赖内存中缓存的 manifest 状态或在进入 filelock 前做检查，易发生经典的 TOCTOU（Time-of-Check to Time-of-Use）竞争漏洞与脏写覆盖。

【修改目标】
1. 重构 manifest.py，确立必须在持有 filelock 临界区内部重新从磁盘读取 manifest.json 并核对 generation 递增版本号；
2. 任何写操作均基于严格的 CAS（Compare-And-Swap）语义：若读取版本与写入前版本不一致，立刻回滚并报错重试；
3. 编写多子进程并发压测单测 test_dual_process_cas.py，断言并发场景下零脏写、零状态丢失。
```
