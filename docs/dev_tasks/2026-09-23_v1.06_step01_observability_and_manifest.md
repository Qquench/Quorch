#### 【缺陷根因与修改目标】
**根因**：
传输层 SSE delta 分片被“即到即写”（Write-on-Arrival）直接追加 `\n` 并打时间戳，将网络传输分片与语义行 1:1 强绑定，导致真实端点下一行只有一个汉字/单词（万行碎片文件膨胀 100 倍）；同时单测中使用整句 mock 制造了假契约（绿测试悖论），导致生产环境下的严重排版崩溃在 CI 中被全程掩盖。
**目标**：
在 `reviewer_engine.py` 实现独立可复用的 `CoalescingTextSink`，将流式输入按自然换行 `\n` 切分为完整行并批量落盘；段落空行原样保留 `"\n"`（不掺时间戳）；超长无换行（`max_line_chars=400`）或空闲时间（`idle_flush_seconds=0.4`）触发安全切分；重写单测为细粒度分片 mock 并注入时钟确定性校验。

#### 【分步改造指引】
1. 在 `reviewer_engine.py` 实现 `CoalescingStats` 与 `CoalescingTextSink`：内部维护 `_pending: str` 缓冲区与 `threading.Lock`；`feed(fragment)` 追加后调用 `_emit_ready_lines()`；
2. `_emit_ready_lines()` 遍历并在遇到 `\n` 时切出完整行；对空白行直接输出 `"\n"` 保持 Markdown 原生空行排版；非空行附加 `f"{iso_ts} [{self.tag}] {line}\n"`；
3. 契约明确边界：`emit_line` 接收已带 `iso_ts`、`[tag]` 与结尾 `\n` 的完整格式化行；底层 `RotatingFileSink.write_chunk_text` 作为透明字节汇（Byte Sink），绝不再追加第二重时间戳或换行，杜绝双时间戳污染（R1）；
4. 支持长度超限（`len(self._pending) >= max_line_chars`）与空闲超时触发强制切分，提供后台 watchdog 定时器在推理停顿时自动刷盘（D7），保障实时可观测性；
5. 保证末行完整性：`close()` 与 `flush(force=True)` 必须强制刷出缓冲区中所有尾残内容（即使末尾无 `\n`），绝不截断丢弃最后一行（D9）；
6. 开放可观测性探针：`CoalescingTextSink.stats` 暴露只读统计量（`lines_emitted`, `total_chars_fed`, `chars_currently_buffered`, `chunks_fed`），供单测直接核验聚合指标（D8）；
7. 在 `consultation.py` 中将流式消费循环内的字符串累加替换为构造 `CoalescingTextSink(sink.write_chunk_text, tag="reasoning")`，在 `async for chunk in client.stream_chat` 循环中调用 `coalescer.feed(reasoning)`，流结束时调用 `coalescer.close()`；
8. 新建 `test_coalescing_sink.py`：测试单字/子串分片聚合、换行保留、Markdown 空行保持、超长行截断、时钟注入空闲刷盘、尾残强制刷出与并发线程安全；
9. 在 `test_reviewer_consult.py` 中重构 mock 为逐字分片与**逐码点（含 CJK 汉字与 Emoji 代理对）细粒度分片喂入**（R2），断言 `stats.lines_emitted` 与真实段落行数严格一致，总行数不再按分片膨胀。

#### 【防御与边缘校验】
- `fragment is None` 视为 `""`；`max_line_chars` 强校验下限钳制（`>=64`）；

#### 【缺陷根因与修改目标】
**根因**：
现状 `RotatingFileSink` 无条件捕获流式推理块。在 `mode: subagent`（IDE 内生子代理、思考 Token 不跨 stdio 边界）下产生**纯空写 I/O 与磁盘日志噪声**；同时若为省 I/O 直接关停 sink，则**跨会话最终裁决证据链彻底断档**，事后无法审计。
**目标**：

```python
# plugins/quench-dev-tasks/server/observability_policy.py
from enum import Enum
from dataclasses import dataclass
from typing import Protocol, Optional, Mapping

class SinkMode(str, Enum):
    STREAM   = "stream"     # engine 模式：流式 CoT -> RotatingFileSink, verdict_enabled=True
    SNAPSHOT = "snapshot"   # subagent/manual：物理旁路流式，仅裁决落盘, verdict_enabled=True
    DISABLED = "disabled"   # 离线/纯人工：流式与裁决均禁用, verdict_enabled=False (D4)

MAX_RECORD_BYTES: int = 16 * 1024  # 16KB 有界截断硬上限 (SSOT 常量 D11)

@dataclass(frozen=True)
class ObservabilityDecision:
    mode: SinkMode
    stream_enabled: bool          # 仅 STREAM 为 True
    verdict_enabled: bool         # STREAM 与 SNAPSHOT 为 True，DISABLED 为 False (D4)
    verdict_path: str             # 归一化后的裁决快照落盘绝对路径 (D3)
    max_record_bytes: int = MAX_RECORD_BYTES

class VerdictAuditSink(Protocol):
    def emit_verdict(
        self,
        *,
        task_id: str,
        verdict_hash: str,
        payload: Mapping[str, object],
        generation: int = 0,      # 不透明整型，解耦 1.4，默认 0 杜绝跳步 (D5)
    ) -> None: ...

def resolve_observability_policy(
    reviewer_mode: str,                # "subagent" | "engine" | "manual" | "disabled"
    *,
    verdict_path: str,
    explicit_disable_verdict: bool = False,
) -> ObservabilityDecision: ...

def make_verdict_sink(path: str, lock_path: Optional[str] = None) -> VerdictAuditSink: ...
```

#### 【分步改造指引】
1. 新建 `observability_policy.py`：实现 `SinkMode` 枚举、`ObservabilityDecision` 冻结数据类、`resolve_observability_policy()` 纯函数与 `make_verdict_sink()` 工厂；
2. 在 `make_verdict_sink` 中基于既有 `FileLock` 原语实现跨进程文件锁，保障行式追加的跨进程原子性（D2）；
3. 实现 `VerdictAuditSink` 的有界安全落盘：单行追加至 JSONL。度量对象严格为完整 JSONL 行（不含末尾换行）的 UTF-8 字节长度（`len(line.encode('utf-8')) <= MAX_RECORD_BYTES`）；超限时执行结构化降级，在保持外层键完整合法的前提下对 `payload` 文本在 UTF-8 边界处安全截断并注入 `{"truncated": true, "orig_bytes": N}`，重新序列化，保证输出恒为合法可解析的 JSONL 行（B4）；

5. 编写 `test_observability_policy.py`，完整覆盖策略分流、零 I/O 旁路、裁决通道恒开、DISABLED 语义与 16KB 截断。

#### 【分步改造指引】
1. 新建 `manifest.py`：声明 `FencedTokenError` 异常与 `TaskRecord`、`Manifest` 数据类，实现 `compute_normalized_md_hash`（规范化哈希，B1）；
2. 实现 `load_manifest`（工作区首次运行自动初始化 generation=0 容器，零破坏性）与 `atomic_replace_manifest`（临时文件 + `os.replace` 原子落盘）；
3. 实现 `commit_lease`、`compare_and_swap` 与 `release_lease`：基于跨进程 `FileLock` 保护原子执行代际比较与自增；`release_lease` 采用留痕墓碑（`released=True`），保留记录与代际，绝不物理删除或重置（B5）；
4. 采样时钟与 Git 容错快照：记录 `git rev-parse HEAD` 哈希，并双写 `monotonic_ns` 与 UTC 墙钟；
5. 在 `templates/quench_stack.yaml` 追加 `governance:` 配置段（`manifest_path: ".agents/.quorch/manifest.json"`，`lease_ttl_seconds: 300`）（B3）；
6. 在 `server.py` 的 `dev_tasks_checkout` 中接入租约签发，在 `dev_tasks_complete` 中接入租约校验与安全释放；
7. 编写 `test_manifest_lease.py`，覆盖单调 CAS、防分裂脑、规范化哈希容错、时钟漂移容错与 Git 分支变动容错。

#### 【防御与边缘校验】
- **规范化 md_sha256 防自失效（B1）**：状态图标变更与人类实施期非结构性注释变更不影响哈希匹配，仅在任务正文结构或受管文件清单被越权修改时拒绝并判定为 fenced；
- **墓碑留痕与跨重启单调持久性（B5）**：`generation` 必须原子持久化存储于 `manifest.json`，释放租约仅置 `released=True`，绝不删除记录或重置 generation，代际跨会话严格单调递增；
- **命名空间防串号（B5）**：以 `<md_stem>::<task_id>` 为键，彻底隔离跨 stage / spec 的同名任务编号；
- **单调 CAS 防分裂脑**：携带旧 generation 的 `release_lease` 必须返回 `False`，严禁修改磁盘文件；
- **时钟回拨容错**：时钟回退时依赖 `monotonic_ns` 差值，不依赖墙钟差值，杜绝假阳性过期；
- **Git 分支切换容错**：检测到 `git_head_sha` 变化时抑制 mtime 维度的过期判定；
- **原子持久化**：写入中断时不残留半写损坏文件，保证 `manifest.json` 始终有效。
