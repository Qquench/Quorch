> **粒度守卫说明**: 核心受管生产代码仅 1 个（`file_scope_guard.py`），远低于 $\le 3$ 核心生产文件上限；测试代码（`test_file_scope_guard_hardening.py`）豁免核心计数。

#### 【缺陷根因与修改目标】
- **根因 1（词法路径判定盲区）**：`file_scope_guard.py` 中的 `is_task_file` 依赖 `os.path.normpath` 词法比较，子代理若创建符号链接（如 `/tmp/link -> docs/dev_tasks/target.md`）或利用 `docs/dev_tasks/../dev_tasks/` 等变体，容易绕过前置拦截直接向任务目录注入未经治理的任务单。
- **根因 2（Windows 跨驱动器异常未捕获，H1）**：`os.path.commonpath` 在 Windows 跨不同盘符（如 `C:` vs `D:`）比较时会直接抛出 `ValueError`。若未包装 `try...except ValueError`，钩子将崩溃阻断正常开发。
- **根因 3（豁免判定先于规范化）**：元文件或特定扩展名豁免逻辑若在 realpath 前执行，攻击者可利用上跳逃逸。
- **修改目标**：在 `file_scope_guard.py` 中引入物理路径归一原语 `resolve_realpath_under`；包装 `try...except ValueError: return None`；确保所有任务单路径比较在 `os.path.realpath` 与 `os.path.commonpath` 归规后进行；若写入目标落入受管任务目录且属于非法逃逸，记录 `DENIED`（`reason="realpath_escape"`）并执行物理阻断。

1. **`file_scope_guard.py::resolve_realpath_under`**：消解软链接、junction 及 Windows 长路径前缀，使用 `try: common = os.path.commonpath([root, target]) except ValueError: return None` 严格比对工作区前缀；对新建文件递归对其父目录做 realpath 处理。
2. **重构任务文件判定次序**：将 `is_governed_task_file` 判定置于物理路径解析之后，保证任何软链接伪装在触及文件系统前被还原为真实物理路径；保留对自定义 `dev_tasks_dir` 的兼容。
3. **单测覆盖**：在 `test_file_scope_guard_hardening.py` 中测试符号链接逃逸、`..` 连续上跳、Windows 跨驱动器盘符比对、非存在新文件的规整判定。

#### 【防御与边缘校验】
- **跨驱动器防御**：`commonpath` 跨盘比对抛出的 `ValueError` 必须捕获并降级返回 `None`，绝不因异常崩溃。
- **性能约束**：钩子单次调用执行时间必须 $\le 50\text{ms}$，严禁引入全盘遍历或子进程调用。
- **审计留痕**：拦截决策经 `log_guard_event` 记录标准事件 `event_type="DENIED"`，附带 `reason="realpath_escape"`。

#### 【缺陷根因与修改目标】
- **根因 1（TargetFile 缺省盲目放行）**：当子代理通过 `run_command` / `bash` 执行类似 `echo "..." > docs/dev_tasks/fake.md` 或 `tee` 重定向时，钩子接收到的 `TargetFile` 为空，现有逻辑直接 `allow` 放行，使前置守卫虚脱。
- **根因 2（进程独立性约束，C1/C2）**：`file_scope_guard.py` 是宿主按每次工具调用独立唤起的子进程，与常驻 FastMCP `server.py` 不共享内存；同时 FastMCP 内部的文件写入并不行经宿主的 `run_command`/`write_to_file`。因此无需虚幻的跨进程 HMAC，而应聚焦于严格拦截外部通过 Shell 命令直接篡写任务单。
- **修改目标**：在 `file_scope_guard.py` 中引入 `detect_shell_write_bypass`，对 Shell 命令参数执行完备的重定向与受管路径识别（覆盖 Bash、PowerShell、Heredoc、Tee 等主流变体）；命中且目标位于受管目录时，执行 Fail-Closed 阻断或提示交互式确认。
