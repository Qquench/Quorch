#### 【缺陷根因与修改目标】
- **根因 1（词法路径判定盲区）**：`file_scope_guard.py` 中的 `is_task_file` / `is_meta_file` 依赖 `os.path.normpath` 词法比较，子代理若创建符号链接（如 `/tmp/link -> docs/dev_tasks/target.md`）或利用 `docs/dev_tasks/../dev_tasks/` 等变体，容易绕过前置拦截直接向任务目录注入未经治理的任务单。
- **根因 2（豁免判定先于规范化）**：元文件或特定扩展名豁免逻辑若在 realpath 前执行，攻击者可利用上跳逃逸。
- **修改目标**：在 `file_scope_guard.py` 中引入物理路径归一原语 `resolve_realpath_under`；确保所有任务单路径比较在 `os.path.realpath` 与 `os.path.commonpath` 归规后进行；若写入目标落入 `docs/dev_tasks/**` 且非内核放行通道，一律执行物理阻断并返回结构化 `deny` / `ask` 决策。

2. **重构任务文件判定次序**：将 `is_governed_task_file` 判定置于物理路径解析之后，保证任何软链接伪装在触及文件系统前被还原为真实物理路径。

#### 【缺陷根因与修改目标】
- **根因 1（前置防线不可能 100% 穷举）**：外部进程直接通过 OS 文件写入、IDE 插件盲点或未受管工具落地的文件，前置钩子无法彻底感知。
- **根因 2（权威登记通道缺失）**：`dev_tasks_propose` 创建任务时未向 `manifest.json` 登记 SHA-256，导致 status 扫描时无法区分合法任务与旁路投毒任务。
- **修改目标**：在 `manifest.py` 增加 `register_proposal` 与 `reconcile_workspace`；在 `dev_tasks_propose` 成功后立即原子登记任务哈希；在 `dev_tasks_status` 扫描时对任务单哈希对账，未登记或被篡改的文件标为 `[UNAUTHORIZED_BYPASS]` 并隔离出可执行队列，同时物理阻断其 `dev_tasks_checkout`。

#### 【目标签名与类型契约】
```python

from typing import Optional, Tuple

    REGISTERED_MATCH      = "REGISTERED_MATCH"       # 已登记且哈希一致

    BRANCH_CHANGED        = "BRANCH_CHANGED"         # git_head_sha 变更引发的正常分支切换漂移
    UNAUTHORIZED_BYPASS   = "UNAUTHORIZED_BYPASS"    # 完全未在清单登记的非法旁路文件

@dataclass(frozen=True)
class ReconcileEntry:

    namespaced_id: Optional[str]
    classification: ReconcileClass
    md_sha256: str
    drift_reason: str = ""

@dataclass(frozen=True)
class ReconcileReport:

def register_proposal(workspace_root: str, *, task_id: str, md_path: str) -> str:
    """在权威清单中登记新任务单的 SHA-256 哈希基线。"""
    ...

def reconcile_workspace(workspace_root: str, dev_tasks_dir: str) -> ReconcileReport:
    """全盘扫描任务单目录并与清单执行后置对账。"""
    ...
```

#### 【分步改造指引】
1. **`manifest.py::register_proposal`**：计算任务单规范化哈希，在文件锁内写入 `TaskRecord`，通过 `atomic_replace_manifest` 安全持久化。
2. **`manifest.py::reconcile_workspace`**：遍历 `dev_tasks_dir/*.md`，对照 manifest 中的哈希记录分类（区分完全未登记与分支切换引起的漂移）；带 `(mtime_ns, size)` 内存快路径缓存优化。
3. **`server.py::dev_tasks_status` 联动**：调用 `reconcile_workspace`；`REGISTERED_MATCH` 正常进入 pending/confirmed 队列；`UNAUTHORIZED_BYPASS` 移入独立的 `bypass_queue`，在输出中显式警示；`dev_tasks_checkout` 前置校验，直接拒绝检出 `bypass_queue` 中的任务。
4. **单测覆盖**：在 `test_manifest_reconciliation.py` 中测试新提案登记、手工投放非法文件隔离、正文漂移识别、分支变更平滑处理、checkout 物理拦截。

#### 【防御与边缘校验】
- **先落盘后登记顺序不变量**：提案流程必须先写任务文件、再登记清单，防止出现清单有记录而文件不存在的幽灵项。
- **checkout 强制门禁**：未获得 `REGISTERED_MATCH` 的任务绝对无法获取执行锁，彻底关闭执行流。
- **向后平滑兼容**：现存已由系统创建的历史合法任务单在初次扫描时提供平滑的指纹自动录入机制，杜绝升级阻断。
