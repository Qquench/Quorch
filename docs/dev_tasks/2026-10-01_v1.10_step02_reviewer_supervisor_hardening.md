#### 【缺陷根因与修改目标】
```
【根因分析】
1. submit() 分配日志后未调用统一定额 GC，形成物理旁路；且准入拒绝、幂等重放、落盘失败以及非正常终态均绕过 unpin，造成永久 pin 泄漏；
2. 跨进程存活判定缺少具体生产者，ActiveLogRegistry 仅为进程内内存结构；且现有保护集未涵盖对端在途作业日志与 latest-*.log 命名空间，在 GC 时易被误删；
3. submit 侧机会式 GC 与终态释放 GC 此前未统一保留期计算，未声明字典序（basename）排序键与纯字符串归一化策略，造成 Zero-stat 契约冲突与断言不可判定；
4. 既有 TERMINAL_STATES（5 元）与新终态集合存在语义分裂，且锁序红线未约束 ActiveLogRegistry._lock 的锁内外部调用。

【修改目标】
1. 建立唯一 unpin SSOT，覆盖全部终态写入者与 submit 的每一条失败分支，保证 pin 与 unpin 严格一一对应；
2. 引入保留条数 SSOT 常量 REVIEWER_TERMINAL_LOG_RETENTION（=40 条 > KEEP=20 条），定义 compute_protected_logs 权威 SSOT（保护集 = 最近 retention 条终态日志 ∪ 全部非终态在途作业日志 ∪ 显式排除 latest-*.log），在 submit 机会式 GC 与终态 GC 两条路径上强制调用；
3. 保护集排序严格依据 basename 字典序（等价于时间序，完全 Zero-stat 兼容）；比对前对 protected_paths 与候选集统一经纯字符串 normcase+normpath+abspath 归一化；删除目标明确为「对可回收候选集收敛至 <= keep」；
4. 实现具体的跨进程存活探测工厂 build_peer_liveness_probe，通过 durable JobRecord 提取 owner_pid / owner_boot_nonce 判定存活，严格遵守 Zero-stat（仅 os.listdir，不 stat 候选日志文件；无 record 时 fail-safe 默认返回 alive）；
5. 正交化终态集合：物理收尾与 pin 释放统一由 PIN_RELEASABLE_STATES（4 元）收敛，单测断言 TERMINAL_STATES == PIN_RELEASABLE_STATES，严令 CANCELLED_PENDING_REAP 期间不得释放 pin；
6. 固化全局锁序（registry_lock -> record_lock -> manifest_lock），reap_dead 采用锁内快照 + 锁外谓词 + 锁内差分写回。
```

#### 【分步改造指引】
1. 在 `log_naming.py` 声明 `REVIEWER_LOG_QUOTA_KEEP = 20` 与 `REVIEWER_TERMINAL_LOG_RETENTION = 40`。`enforce_unified_log_quota` 候选枚举仅匹配 `*.log`（显式排除 `latest-*.log`、`.jsonl` 与索引），并在比对 `protected_paths` 与 `registry.is_pinned` 前统一应用纯路径规范化。
2. 在 `reviewer_jobs.py` 实现 `compute_protected_logs`：扫描 durable JobRecord，按 basename 字典序提取最近 `retention` 条终态日志，合并所有 `state in {QUEUED, RUNNING, CANCELLED_PENDING_REAP}` 的在途日志，排除 `latest-*` 命名空间后返回。
3. 实现 `build_peer_liveness_probe`：以 `os.listdir` 遍历 durable JobRecord，仅通过读取 record 内容判定 owner 存活性，绝对不执行 `os.stat` 候选日志文件；若无匹配 record 时默认极性 fail-safe 返回 alive。
4. 实现 `_pin_log` 与 `_release_log_pin`。统一并执行权威的 `submit()` 步骤序：
   `准入判定 (CapacityLimiter) → 幂等键查重 (命中直接返回既有 record，不二次组装上下文也不二次 pin) → [fail-closed 沙箱检查与上下文组装截断] → allocate_log_file() → _pin_log() → 落盘 JobRecord → 机会式清理 (传入 compute_protected_logs)`。异常分支在 `except` 中必须调用 `_release_log_pin` 回滚并原样抛出。
5. 重构 `TERMINAL_STATES = PIN_RELEASABLE_STATES`。终态写入者在释放 record lock 文件锁之后，仅当 `record.state in PIN_RELEASABLE_STATES` 时才释放 pin；`CANCELLED_PENDING_REAP` 期间严禁释放 pin。随后调用 `compute_protected_logs` 传入配额清理。
6. `ActiveLogRegistry.reap_dead` 改造为：锁内浅拷贝快照 → 锁外执行 `is_alive` 谓词 → 锁内差分写回（仅当快照依然在册时剔除），杜绝锁内外部调用。
7. 编写 `test_reviewer_jobs_log_quota.py`、`test_log_quota_cross_process.py` 与 `test_reviewer_log_retention_semantics.py`，断言 pin 闭环、保留期内 20 次提交后仍可读、verdicts.jsonl 与 latest-*.log 永不误删、跨进程在途日志不可回收、`TERMINAL_STATES == PIN_RELEASABLE_STATES`。

#### 【防御与边缘校验】
- **锁序红线**：全局锁序固定为 `registry_lock → record_lock → manifest_lock`，只允许降序获取，严禁升序；锁内禁止任何外部调用或耗时探测。
- **保护集语义红线**：`compute_protected_logs` 必须覆盖终态保留窗口、所有非终态在途作业（含 `CANCELLED_PENDING_REAP`）并排除 `latest-*`；submit 机会式 GC 与终态 GC 必须均强制调用。
- **排序键红线**：终态保留排序严格依据 `log_path` 的 basename 字典序，零系统调用，时间序等价保证。
- **pin 对称红线**：任何一条返回路径都不得留下未配对的 pin；`_release_log_pin` 必须幂等且绝不抛出。
- **状态正交红线**：`CANCELLED_PENDING_REAP ∉ PIN_RELEASABLE_STATES`，直到重计费完成跃迁为最终终态才可释放 pin。
- **Zero-stat 红线**：候选枚举阶段仅允许 `os.listdir`，不得引入 `os.stat` / `os.path.exists` / `Path.exists`（CI Case 6）。
