#### 【缺陷根因与修改目标】
```
【根因分析】
test_windows_api_exit_code_scenarios 在单测中直接使用 patch("ctypes.windll", ...)。由于 CPython 仅在 os.name == 'nt' (Windows) 时在 ctypes 模块注入 windll 属性，在 POSIX (Ubuntu/macOS) 宿主上 ctypes 无此属性。unittest.mock.patch 在未指定 create=True 时无条件调用 get_original()，导致 Ubuntu CI 抛出 AttributeError: <module 'ctypes'> does not have the attribute 'windll'。

【修改目标】
1. 在 test_workspace_lease.py 的 test_windows_api_exit_code_scenarios 中为 3 处 patch("ctypes.windll", ...) 添加 create=True，确保非 Windows 平台安全注入并在退出时自动回收；
2. 新增 test_windll_patch_leaves_no_residue 守卫单测；
3. 在 docs/ci_incident_tracker_and_compatibility_guide.md 登记 INC-20260925-01 并在案例档案中归档【案例 7】。
```

#### 【目标签名与类型契约】
```
def test_windows_api_exit_code_scenarios(temp_workspace): ...
def test_windll_patch_leaves_no_residue(temp_workspace): ...
```

#### 【分步改造指引】
1. 修改 test_workspace_lease.py 中的 test_windows_api_exit_code_scenarios，将 3 处 patch("ctypes.windll", ...) 改为 patch("ctypes.windll", MagicMock(kernel32=mock_kernel32), create=True)；
2. 在该测试后追加 test_windll_patch_leaves_no_residue 测试，验证 patch 退出后在非 win32 环境下 ctypes 无 windll 残留；
3. 更新 docs/ci_incident_tracker_and_compatibility_guide.md：在 §2.1 故障总账追加 INC-20260925-01，在 §3 追加案例 7 详细分析与防御闭环。

#### 【防御与边缘校验】
严禁使用 pytest.mark.skipif 跳过测试；
create=True 注入的属性由 unittest.mock.patch 在退出时通过 delattr 安全回收，不污染全局运行环境；
平台无关性断言：非 win32 宿主在用例执行完毕后确保 ctypes 不含 windll 残留。
