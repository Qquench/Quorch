#### 【缺陷根因与修改目标】
```
【根因分析】
根因一：cache 命中指标若无滚动生命周期治理，数据文件将随长期开发无界增长，破坏工作区 .agents/logs 配额边界；
根因二：log_naming.py 中 norm_registry_key 现存轮转折叠正则 r"\.\d+\.log$" 且替换目标硬编码 ".log"，既不支持 .jsonl 轮转，若强行采用交替式正则 r"\.(?:\d+\.(log|jsonl)|(log|jsonl)\.\d+)$" + 单引用 r".\1"，会因交替分支产生【两个不同编号捕获组】，在 .log.1 / .jsonl.1 形态下组 1 不参与匹配而塌缩为 "."，导致 registry 键错误、活跃分片被 GC 误删；
根因三：prompt_hash 若采用每次随机盐会破坏跨运行聚合，明文则存在上下文泄露风险；该哈希作为 best-effort 聚合键，并非安全隔离边界；
根因四：在异步协程内直接执行阻塞式文件锁与磁盘 I/O，可能导致事件循环卡顿，违背 50ms 响应约束；若采用二分字节截断会导致行内 JSON 语法破损，破坏 tail-reader 容错。

【修改目标】
1. 修复 log_naming.py 的 SSOT 正则：采用【单一捕获组】r"(?:\.\d+)?(\.(?:log|jsonl))(?:\.\d+)?$"，replacement 统一为 r"\1"，使 .1.log/.log.1 -> .log 且 .1.jsonl/.jsonl.1 -> .jsonl 四种形态均正确折叠，扩展名经反向引用严格保留，无后缀输入恒等幂等；
2. 新增轻量 RollingJsonlTelemetrySink，单行仅存元数据数值指标（prompt_tokens、cached_tokens、miss_tokens、hit_ratio、prompt_hash），严禁写入 Prompt 全文；
3. 定义专用 TELEMETRY_RECORD_BYTES = 4 * 1024 上限（彻底解耦 verdict sink 的 MAX_RECORD_BYTES），实现按文件大小 max_bytes 和滚动代数 max_rotations 的 FIFO 滚动（超限以 os.replace 原子轮转为 .1.jsonl），并接入 ActiveLogRegistry 与配额体系；
4. prompt_hash 使用基于 workspace_root 的【工作区确定性盐】截断哈希，作为 best-effort 跨会话聚合键，保证同工作区前缀可聚合比对；
5. 单条记录超出 TELEMETRY_RECORD_BYTES (4KB) 时，执行【字段级降级】（截断 session_id/mode 等自由文本字段并记录长度，或整条安全丢弃），严禁采用字节级截断破坏 JSON 语法完整性；
6. 并发追加使用 filelock.FileLock（超时 5.0s），在异步上下文内一律强制通过 `await sink.aemit(...)`（内部调用 asyncio.to_thread）卸载，绝不阻塞主事件循环；写锁异常仅打印 stderr 告警，绝不抛出异常阻断主审查流程。
```
