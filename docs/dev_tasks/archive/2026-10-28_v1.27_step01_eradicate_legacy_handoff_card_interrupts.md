#### 【缺陷根因与修改目标】
```
根因：
1. 服务端 dev_tasks_checkout 在已确认队列为空且存在待确认/返工任务时，硬编码返回带有 legacy_card_markdown 的 handoff_card，并在 instruction 中要求“输出【Quench 任务交接卡】，引导用户在新会话切换至自选的高阶架构审查模型进行审查修订”，直接导致主模型接收到非预期的打断指令而停顿。
2. 服务端 dev_tasks_escalate 硬编码指令“向用户输出【Quench 任务交接卡】，等待用户在新会话中由高阶架构审查模型完成审查修订”。
3. reporting.py 中 render_handoff_card 文本写死“点击 + 开启新的纯净会话”，未感知外部 Reviewer API / 子 Agent 自动化审查能力。
4. AGENTS.md 与 dev-tasks-discipline.md 缺乏标准模式下提出任务后通过 dev_reviewer_submit 带内自动审查的正向接力闭环规范，遗留手工开新会话描述。

目标：
1. 重构 dev_tasks_checkout 与 dev_tasks_escalate 的 instruction 与 message，使其完全与 Autopilot harness_next_action 接力契约对齐，在具备自动化通道时严禁下发“开新会话抛交接卡”等刹车指令。
2. 升级 render_handoff_card 支持策略感知（engine 优先调用 dev_reviewer_submit / refine_spec，subagent 派发子代理，仅 manual 降级为开新会话）。
3. 全面更新 AGENTS.md、dev-tasks-discipline.md 与 workflow skill，确立标准模式下 Propose -> Reviewer Submit -> Poll -> Confirm -> Checkout 自动闭环纪律。
4. 编写专门的单元测试，确保全量测试 100% 绿灯且无向后兼容性破坏。
```
