#### 【缺陷根因与修改目标】
```
【根因分析】
在 test_reviewer_consult.py 的 test_timeout_breaker_returns_degraded_and_keeps_partial_log 中，设定 timeout_seconds = 1 且底层 sleep 2.0s，断言 assert elapsed < 2.5。在 GitHub Actions 虚拟化 Windows 宿主（ProactorEventLoop 调度与多任务 CPU 抢占）高负载时，从触发 TimeoutError、写入日志 flush 到用例恢复共耗时 2.609s，仅比 2.5s 慢了 0.109s，由于测试缺少调度抖动余量导致偶发红灯（Flaky）。

【修改目标】
1. 解耦行为正确性断言与耗时容差，保留宽松护栏（assert elapsed < 5.0）并强化熔断不变量；
2. 登记 INC-20260925-02 事故并在防护手册中形成准则 7 闭环。
```

#### 【目标签名与类型契约】
```
def test_timeout_breaker_returns_degraded_and_keeps_partial_log(tmp_path: Path, monkeypatch): ...
```

#### 【分步改造指引】
1. 修改 test_reviewer_consult.py 中的 test_timeout_breaker_returns_degraded_and_keeps_partial_log：将 assert elapsed < 2.5 调整为更合理的松弛防死循环护栏（assert elapsed < 5.0, f"Consultation timed out exceeded runaway budget: {elapsed}s"），并在断言信息中补充打印 status、degraded_reason 和耗时，重点验证熔断状态与 partial log 落盘不变量；
2. 更新 docs/ci_incident_tracker_and_compatibility_guide.md：在 §2.1 故障总账登记 INC-20260925-02，更新 INC-20260925-01 修复提交为 8f97709；在 §3 历史案例归档追加【案例 8：测试断言紧贴超时边界导致 CI 虚拟化宿主调度抖动偶发 Flaky】；在 §4 跨平台安全编码准则补充【准则 7：异步超时熔断测试严禁紧贴边界断言墙钟时长】。

#### 【防御与边缘校验】
严禁使用紧贴超时的硬编码墙钟耗时（如 < 2.5s）作为异步熔断正确性的判据；
针对 CI 共享虚拟化环境的调度与时钟抖动，保留宽松死循环护栏（assert elapsed < 5.0）并优先断言熔断行为强不变量；
断言失败时必须输出清晰的调试信息（status, degraded_reason, elapsed）；
确保单测在 Windows 和 POSIX 平台上 100% 具备确定性。
