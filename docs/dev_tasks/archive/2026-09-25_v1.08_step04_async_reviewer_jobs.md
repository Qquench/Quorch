#### 【缺陷根因与修改目标】
```
【根因分析】
1. Reviewer 异步化若允许多个独立的 MCP Server 进程针对同一 workspace 并发启动对账（reconcile），
   异进程启动时会因 owner_boot_nonce 校验不符，将正在运行的他进程合法在途推演误判为 ORPHANED；
2. 误判为 ORPHANED 会直接触发 unpin 操作，导致双 GC 回收路径误删活跃在途日志，在 Windows 下触发
   WinError 32 崩溃，在 POSIX 下写向匿名 inode 丢失长思考流；
3. 判定器 probe_peer 若边界语义模糊：
   - POSIX 下跨用户进程访问时 os.kill(pid, 0) 抛出 PermissionError (EPERM)，若被笼统判死将直接误杀活跃任务；
   - PID 复用（PID reuse）时，仅判断 PID 存活无法识别同机器异代进程；
   - Windows 平台仅靠 os.kill(pid, 0) 无法感知已退出但句柄未全关的僵尸状态；
4. 租约若缺少独立保活线程模型，长同步推理阻塞主事件循环时会发生假死（心脏骤停）被他人夺权。

【修改目标】
1. 建立基于文件锁与心跳租约的 workspace 独占持有者机制（WorkspaceLeaseGuard），在服务启动时获取；
2. 严格限定 4.0 职责边界：只负责「互斥 + 存活性判定 + 租约保活」，绝不越界调用 Task 4.1 尚未实现的 unpin/清理；
3. 提供严格边界防守的 probe_peer 存活性判定：
   - POSIX 下捕捉 PermissionError (EPERM) 确认为存活（is_alive=True, takeover_allowed=False）；
   - PID 存活但 boot_nonce 不符时判定为异代进程，严格返回 takeover_allowed=False（保守拒绝）；
   - Windows 平台通过 OpenProcess(SYNCHRONIZE|PROCESS_QUERY_LIMITED_INFORMATION) + GetExitCodeProcess
     精确判定 STILL_ACTIVE，并辅以 GetProcessTimes 比对创建时间推导 nonce；
4. 提供后台独立心跳守护线程（LeaseHeartbeatThread），解耦主工作线程，防止长任务推演造成租约意外超时；
5. release() 实现完全幂等，二次调用或无锁状态安全无异常。
```

@dataclass(frozen=True)
class PeerLiveness:
    is_alive: bool
    pid: int
    boot_nonce: str
    takeover_allowed: bool       # 仅当确认进程真实死亡或租约超时且 PID 无复用时为 True

class WorkspaceLeaseGuard:
    def __init__(
        self,
        workspace_root: Path | str,
        *,
        lease_ttl_s: float = 300.0,
        heartbeat_interval_s: float = 30.0,
    ) -> None:
        assert 0 < heartbeat_interval_s < lease_ttl_s  # 导入期与初始化不变量断言 (N2)
        ...

    def is_held(self) -> bool: ...  # 运行时租约持有判定 (F5/B6)
    def acquire_or_probe(self, boot_nonce: str) -> bool: ...
    def start_heartbeat_thread(self) -> None: ...
    def stop_heartbeat_thread(self) -> None: ...
    def touch(self) -> bool: ...
    def release(self) -> None: ...  # 保证幂等：多次调用、未持有锁或盘上文件已删均安全返回 (N1)

    def probe_peer(pid: int, boot_nonce: str, workspace_root: Path | str) -> PeerLiveness:
        """跨平台高可靠进程存活与代际探针。
        - POSIX: os.kill(pid, 0) 遇 PermissionError (EPERM) => is_alive=True, takeover_allowed=False
        - Windows: OpenProcess + GetExitCodeProcess == STILL_ACTIVE

        - 仅当 ProcessLookupError 或 ExitCode != STILL_ACTIVE => is_alive=False, takeover_allowed=True

#### 【防御与边缘校验】
- **EPERM 存活断言**：模拟 `os.kill` 抛出 `PermissionError` 时，`probe_peer` 断言返回 `is_alive=True, takeover_allowed=False`，绝不误杀。
- **PID 复用保守拒绝**：当 PID 物理存在但盘上记录的 `boot_nonce` 与探测目标不一致时，断言 `takeover_allowed=False`。
- **Windows 真实退出码**：Windows 下进程终止但句柄未全关时，通过 `GetExitCodeProcess` 验证非 `STILL_ACTIVE` 方判为死亡。
- **独立线程保活防骤停**：在主线程执行 `time.sleep(2)` 模拟重任务阻塞，断言后台心跳线程能正常更新租约文件时间戳。
- **release 幂等性**：对未持锁、二次 release、外部 unlink 租约文件的实例调用 `release()`，断言无任何异常抛出。

#### 【防御与边缘校验】
- **CAS 单写者与写入原子性**：并发注入 complete 与 cancel，断言终态唯一、先写胜出；JobRecord 写入由 temp+os.replace 保证原子，写侧遇 WinError 32 有界重试，并发 Poll 绝不抛 JSONDecodeError。
- **孤儿重启对账与跨进程防护**：结合 Task 4.0 probe_peer 验证，断言其在途任务仅在所有者 PID 确实死亡时迁为 ORPHANED，异进程存活时不被误杀。
- **连接物理截断与计费留存**：断言 cancel 后底层连接真正被 close，Worker 停止 decode，tokens_billed_after_cancel 仅在 CANCELLED 终态诚实落地。
- **双 GC 路径防撕与轮转归并 (N-1)**：断言形如 `YYYYMMDD_NNN_slug.1.log` 的轮转分片文件经 `norm_registry_key` 自动与主日志共享 pin 状态，GC 期间绝不误删。
- **无租约禁触 GC (LEASE-GATE, N-2)**：断言 Reviewer 通道下未持有 workspace lease 时调用 GC 抛出 `WorkspaceLeaseNotHeldError`；同时断言 legacy 旧单测在默认 `require_lease=False` 下零破坏回归。
- **白名单 1KB 强约束与零上下文膨胀**：断言非终态 Poll 快照经 project_nonterminal 投影严格等于 6 个白名单字段；断言 compact 序列化 <= 1024 字节；注入长字段断言 SnapshotContractViolation 抛出且绝不截断；断言无任何 reasoning 原文泄漏。
- **终态对称双源投影 (N-3)**：断言终态输出经 `project_terminal(record, result)` 投影键集严格等于 POLL_TERMINAL_FIELDS，断言 set((result or {}).keys()) ∩ {"reasoning", "raw_reasoning", "chain_of_thought"} == ∅。
- **会话防越权 (IDOR)**：以非任务所属的 session_id 发起 poll 或 cancel，断言抛出 PermissionError 拒绝访问。
- **转译与 i18n 安全**：服务端返回纯结构化数值与英文 enum，format_progress 注入 env 在 en 与 zh 下 6 种状态枚举均能精准转译，测试覆盖率 100%。
- **薄壳向后兼容**：既有 dev_reviewer_consult 调用在正常场景与超时场景下，其返回结构与老接口逐字段一致。
