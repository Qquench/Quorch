#### 【缺陷根因与修改目标】
```
【根因分析】
根因一：当前 consultation.py (render_mode_prompt) 与 server.py (dev_tasks_refine_spec) 在组装用户消息时，将高度动态的 query、task_id、title 放置在长篇代码切片之前。DeepSeek 缓存引擎采用严格从 Token 0 起的精确前缀匹配（64-token 块对齐），提问或 ID 的任何微小差异，直接导致排在其后的数千至数万 Token 代码上下文与输出协议全量发生 Cache Miss，命中率暴跌至接近 0%；
根因二：.agents/quench_stack.yaml 中配置 architecture_doc: "docs/architecture.md"，该文件路径在工作区并不存在（实际路径为 docs/architecture/README.md），导致全局架构基准未能挂载进 System Prompt，损失了数千 Token 的可稳定复用基线；
根因三：切片组织未强制使用确定性的相对路径字母排序，存在因文件顺序不同导致前缀指纹漂移的风险；
根因四：CodeSlice 目前定义在 consultation.py 中，而 PromptAssembler 位于 reviewer_engine.py，若直接在 reviewer_engine.py 中导入 CodeSlice 会与 consultation.py 产生循环引用（Circular Import）。

【修改目标】
1. 修正 .agents/quench_stack.yaml 中 architecture_doc 路径为 docs/architecture/README.md，使核心架构规范稳定入驻 System 缓存前缀；
2. 构建 Prompt 四段式“稳定性梯度”拓扑：①静态系统基准前缀 -> ②模式指引与格式协议 -> ③按相对路径字典序排序的代码切片（去绝对路径、去 mtime） -> ④【绝对尾置】动态 Query 与 Task ID；
3. 锁定 CodeSlice 契约（保持字段名 text 与位置序 rel_path, start_line, end_line, text 100% 兼容不变；为保护既有消费者的 __dict__/weakref/反射与位置参数构造，显式保持无 slots 的 @dataclass(frozen=True)；新类 AssembledPrompt 则正常启用 slots=True），将其定义下沉至 reviewer_engine.py，并在 consultation.py 中保留兼容直通导出 `from reviewer_engine import CodeSlice`，在 reviewer_engine.py 中补充 Sequence 导入，彻底解决循环依赖；
4. 为组装器增加 prefix_hash 纯哈希导出能力（仅作为单测断言与遥测账本索引，非安全边界）；
5. 同步改造 dev_tasks_refine_spec 的提示词拼接逻辑，将 task_id 与草案文本后置。
```

#### 【目标签名与类型契约】
```
# reviewer_engine.py 既有 typing 导入块中追加: Sequence
from typing import Sequence, Optional, Mapping, Any

@dataclass(frozen=True)
class CodeSlice:
    rel_path: str
    start_line: int
    end_line: int
    text: str

@dataclass(frozen=True, slots=True)
class AssembledPrompt:
    stable_prefix: str    # 段① (系统基准) + 段② (模式协议)
    context_block: str    # 段③ (代码切片，纯相对路径无mtime)
    dynamic_tail: str     # 段④ (提问与动态参数)
    prefix_hash: str      # sha256(stable_prefix + "\x00" + context_block)[:16] (索引/断言用途)

class PromptAssembler:
    @staticmethod
    def assemble_consultation_prompt(
        *,
        mode: str,
        slices: Sequence[CodeSlice],
        query: str,
    ) -> AssembledPrompt: ...
```

#### 【分步改造指引】
1. 修正 .agents/quench_stack.yaml，将 architecture_doc 指向真实存在的 docs/architecture/README.md；
2. 将 CodeSlice 定义从 consultation.py 迁移至 reviewer_engine.py，严格保持 `@dataclass(frozen=True)`（不加 slots）以及字段名 `text` 与构造顺序不变，并在 consultation.py 中保留 `from reviewer_engine import CodeSlice` 以维持向后兼容性；
3. 在 reviewer_engine.py 既有 typing 导入块中追加 `Sequence`，重构 PromptAssembler，定义 AssembledPrompt 四段式数据结构与纯函数组装流水线，输出前缀稳定哈希 prefix_hash；
4. 重构 consultation.py 中的 render_mode_prompt，将通用模式指引和输出协议提升至代码切片之前，代码切片按 rel_path 字典序排序，Query 严格移至最末尾；
5. 重构 server.py 中的 dev_tasks_refine_spec 组装逻辑，将动态 task_id 与 raw_spec 移到代码上下文和输出契约之后；
6. 编写 test_prompt_cache_stability.py，断言相同代码切片两次组装 prefix_hash 绝对一致、仅改变 query 时前缀哈希不变、前缀无任何绝对路径与时间戳，并断言 CodeSlice 跨模块导入构造 `CodeSlice(rel_path, start, end, text)`、`.text` 访问以及 `dataclasses.asdict` 键序完全零回归。

#### 【防御与边缘校验】
CodeSlice 下沉必须保持无 slots、字段名 text 与参数位置序 100% 一致，严禁引发既有构造点的 TypeError 或破坏 weakref/__dict__
相同 mode 与切片输入下两次调用 assemble 产出的 stable_prefix 与 context_block 字节必须 100% 绝对一致，杜绝任何隐式动态注入
前三段稳定前缀中严禁混入任何 datetime、mtime、系统时间戳、随机 UUID 或会话标识符字面量
代码切片锚点必须使用规范的 Posix 相对路径（严禁使用操作系统绝对路径或 Windows 反斜杠）
quench_stack.yaml 中配置的 architecture_doc 文件在工作区中必须客观真实存在，挂载失败时平滑降级并记录告警，不抛致命异常
Query、Task ID 及会话标识仅允许出现在第四段动态尾部，确保截断点之前的超长前缀永远位于缓存命中的物理有效区内
