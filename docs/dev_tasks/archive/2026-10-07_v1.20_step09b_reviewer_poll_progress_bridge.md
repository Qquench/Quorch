#### 【缺陷根因与修改目标】
```
Root Cause:
1. 在途推演黑盒与刷屏：dev_reviewer_poll 长轮询在 await asyncio.sleep 期间对 MCP 客户端完全静默，缺乏存活可见性。
2. 循环计时算术缺陷：min(0.25, timeout_s - elapsed) 混用“轮次预算”与“作业已耗时”，当作业耗时 > timeout_s 时 sleep 参数 <= 0，在 asyncio 下等价于 sleep(0)，导致紧循环热旋与高频状态读取 IO 风暴；且终态判定依赖解析 raw_text 字符串，逻辑脆弱。

Goal:
1. 在 reviewer_jobs.py 抽出 JobProgress（frozen dataclass）与 progress_snapshot() 纯读 SSOT，并新增非投影终态访问器 is_terminal_state()。
2. dev_reviewer_poll 以单调时钟死线重构循环（sleep 下限 0.05s），首拍即时发射、其后 1.0s 经 ctx.report_progress 发射 format_heartbeat_line(tokens, job_elapsed_s)。
3. 零契约变更：ctx 末位追加保证位置参数兼容，且声明必须由 inputSchema 逐字节快照测试物理证明，而非散文声明。
```

#### 【目标签名与类型契约】
```python
from fastmcp import Context

@dataclass(frozen=True)
class JobProgress:
    tokens: int
    elapsed_s: float          # 作业自提交起已耗时（供心跳文案）
    state: str                # 复用 JobRecord 状态枚举，禁止自造字符串

class ReviewerJobSupervisor:
    def progress_snapshot(self, job_id: str, session_id: str) -> JobProgress | None:
        """纯读、无副作用、不跨 await 持锁。None = 作业不可见（不存在 / session 不匹配 / 已终态）。"""
    def is_terminal_state(self, job_id: str, session_id: str) -> bool:
        """非投影终态访问器；禁止通过解析 raw_text 字符串判定终态。"""

@mcp.tool()
async def dev_reviewer_poll(
    workspace_root: str,
    job_id: str,
    session_id: str,
    wait_max_s: int = 0,
    raw_text: bool = True,
    ctx: Context = None,          # 必须末位追加：不得破坏既有位置参数绑定
) -> Union[str, dict[str, Any]]: ...
```

#### 【分步改造指引】
1. **循环重构（先修 B2 热旋与脆弱终态）**：
   - `timeout_s = max(0, min(25, int(wait_max_s)))`；`timeout_s == 0` 直接返回单次 `supervisor.poll(...)`。
   - 否则建立单调时钟死线 `deadline = time.monotonic() + timeout_s`。
   - 循环体中：`poll(...)` → `supervisor.is_terminal_state(...)` 短路返回 → `remaining = deadline - time.monotonic()`，若 `remaining <= 0` 直接返回 → 到点发射进度（首拍 `next_tick = time.monotonic()` 即时） → `await asyncio.sleep(min(0.25, max(0.05, remaining)))`。
2. **进度发射封装（修 B3 隔离与背压）**：
   - 独立协程 `_emit_poll_progress(ctx, tokens, elapsed_s, timeout_s, consumed_s)`。
   - 若 `ctx is None` 或无 `report_progress` 直接 return；
   - 载荷规整：`progress=consumed_s`、`total=float(timeout_s)`、`message=format_heartbeat_line(tokens, elapsed_s)`（限制 128 字符）。
   - `await asyncio.wait_for(coro, timeout=0.2)`；`except asyncio.CancelledError: raise` 透传取消；其余 `except Exception: pass`。
3. **SSOT 收敛与终态访问器**：
   - 在 `reviewer_jobs.py` 中 `JobProgress` 为既有 `record.progress` 的派生视图，不得引入第二真源；`tokens` 取内存活记录（worker 持续更新），禁止取磁盘 durable 快照。
   - 实现 `supervisor.is_terminal_state(job_id, session_id) -> bool`。
4. **签名末位追加与文档同步**：
   - `ctx: Context = None` 末位追加在 `raw_text` 之后。
   - 更新 `dev_tasks_mcp_specification.md §16`（注明 MCP progress notification 与 best-effort 特性）。
   - 在 `docs/roadmap/v1.20_architecture_slimming_roadmap.md` 注册 step09b 章节。
5. **纪律契约与单元测试**：
   - 在 `test_anti_roleplay_discipline_contract.py` 增补断言：进度 `message` 必须逐字节等于 `format_heartbeat_line` 输出，禁止自由文本或 findings 内容泄露（INV-3）；服务端仍不得出现 `print()`（INV-4）。
   - 编写 `test_reviewer_poll_progress.py`，覆盖 A1–A9 全部断言。
6. **DoD 验证命令**：运行全量验证命令，确认全部测试通过且资产清单无漂移。

#### 【防御与边缘校验】
- **热旋防线**：sleep 下限 0.05s；断言 poll 调用次数 <= `timeout_s/0.25 + 2`、累计 sleep <= `timeout_s + 0.3s`。
- **背压防线**：通知发送 `wait_for` 0.2s 截断，保证总耗时 <= `timeout_s + 0.5s`，即使客户端完全不读通知。
- **取消语义**：`CancelledError` 必须透传；等待中 `dev_reviewer_cancel` 后 <= 0.5s 返回 CANCELLED 投影且此后零通知。
- **零契约漂移**：`inputSchema` 快照逐字节相等；`"ctx" not in schema.properties`；`wait_max_s` <= 25 且默认 0；位置参数兼容（`(ws, jid, sid, 25, False)` 仍绑定 `wait_max_s/raw_text`）。
- **不越界**：`progress_snapshot` 纯读、`JobRecord` mtime_ns 不变、不跨 await 持锁、不触碰 workspace lease 与 manifest filelock（INV-1 不受影响）。
- **降级无害**：`ctx is None` / 无 `progressToken` / 通知抛异常 -> 返回路径与改动前逐字节一致。
