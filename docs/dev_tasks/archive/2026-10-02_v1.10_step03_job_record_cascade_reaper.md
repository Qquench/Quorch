#### 【缺陷根因与修改目标】
```
【根因分析】
1. 根因（Critical）：日志与记录被拆为两个独立保留域（LOG_QUOTA_KEEP=20 vs TERMINAL_LOG_RETENTION=40 vs RECORD_RETENTION=40），三者需持续人工同步；任务 1.1 通过 protected_paths 透传来"维持同步"，属为自造不变量新增守护机制，非除根因；
2. 衍生（Critical）："两阶段级联"仅因双域分离而存在；任何为降延迟而将 enforce_unified_log_quota 移出锁的未来重构会立即复现 TOCTOU；
3. 衍生（High）：Zero-stat 全局红线与 os.remove 的 TOCTOU 异常处理自相矛盾，且 rmdir 吞并已定义而 unlink 吞并缺失，存在半成品回收状态；
4. 衍生（High）：owner_boot_nonce 活锁逃生在字段缺失/迁移/容器重启场景下会误判活作业为死，造成在途评审结果丢失；
5. 衍生（Medium）：submit 热路径节流 + 单飞 mutex + acquire 超时跳过，在竞争中会永久跳过 GC，反而造成 jobs 目录无界增长。

【修改目标】
1. 将 jobs 保留收敛为单一域：每作业以 <session_id>/<job_id> 前缀同目录持有 .log/.record.json/.result.json，仅保留唯一常量 REVIEWER_JOB_RETENTION=40；
2. 删除双域协调机制：移除 compute_protected_logs、protected_paths 透传、CascadeGcReport 五字段、孤儿差集回收；
3. GC 简化为单遍：按 log basename 名序取超窗 session 目录并 rmtree，一次完成日志+记录+结果回收；
4. 撤销 Zero-stat 全局红线（保留 _guarded_stat 事故点修复），允许 os.path.exists；
5. 删除 owner_boot_nonce；以 filelock 可获取性作为唯一活性判定；
6. 移除 submit 热路径节流/单飞/超时跳过，改为加载期一次性 GC。
```

#### 【分步改造指引】
1. 在 log_naming.py 定义 `REVIEWER_JOB_RETENTION = 40` 与显式 `if not (...): raise AssertionError(...)`；删除旧的 `REVIEWER_LOG_QUOTA_KEEP` / `REVIEWER_RECORD_RETENTION` 及 SSOT 一致性断言。
2. 将 jobs 落盘布局统一为 `<session_id>/<job_id>.log|.record.json|.result.json`（若现布局不同，提供一次性迁移或向后兼容读取垫片）。
3. 重写 `gc_terminal_jobs`：单次 `os.listdir` 取 session 目录 → 按 log basename 名序排序 → 对超窗目录 `shutil.rmtree` 并吞并 `FileNotFoundError`。
4. 删除 `compute_protected_logs` 与其调用点；删除 `enforce_unified_log_quota` 的 `keep`/`registry`/`protected_paths` 协调逻辑（其独立配额职责由 S1 单域取代）。
5. `reconcile_on_load` 内调用一次 `gc_terminal_jobs`；**移除** submit 路径的计数器/单飞 mutex/acquire 超时跳过。
6. 活性判定改为：尝试 acquire 该作业的 filelock；成功即判死，迁移至 ORPHANED 并纳入本轮回收；删除全部 `owner_boot_nonce` 分支。
7. 撤销 Zero-stat 全局禁令：回收路径允许 `os.path.exists`；仅保留 `log_naming._guarded_stat` 的路径白名单事故点修复。
8. poll 及日志读取在 record/result/log 缺失时仍优雅降级为 `record_pruned` / `log_pruned`（此行为必须保留）。
9. 编写 `test_job_retention_single_domain.py`，覆盖下方断言。

#### 【防御与边缘校验】
- **单域不变量**：同一 session 目录内 .log/.record.json/.result.json 必须同生共灭；断言不存在"记录在而其 log 已删"的墓碑态（该状态在单域下不可表达）。
- **名序单调主键**：以 log basename 为唯一第一排序键；latest-* 及非规范名显式排除或稳定兜底。
- **异常吞并完备**：rmtree/unlink 路径必须吞并 ENOENT/ENOTEMPTY/EACCES/FileNotFoundError，严禁半成品回收。
- **活性判定无假死**：字段缺失/迁移场景下不得误判活作业为死；以 filelock 可获取性为唯一判据。
- **无节流泄漏**：submit 路径不得因竞争而跳过回收导致无界增长；回收仅在加载期执行。
- **显式 raise 红线**：模块加载期核心不变式统一使用显式 `raise`，杜绝 `python -O` 静默剥离。
