#### 【缺陷根因与修改目标】
```
Root Cause: workspace_lease.py 中的 probe_peer 跨平台进程嗅探（POSIX os.kill(pid,0) / Windows
OpenProcess+GetExitCodeProcess）与后台 LeaseHeartbeatThread 心跳线程属分布式过度设计。A1 单机单用户
公理下，崩溃 worker 回收无需实时进程嗅探——TTL 超时 + generation CAS 拒绝过期写即可覆盖。

【Reviewer R1 新识别缺口】删除心跳线程后，is_held() 内嵌的 0.8·lease_ttl_s 新鲜度判定失去刷新来源，
持有者自身在长任务中将被误判失活（真实失效模式，非理论边缘）。因此本任务必须同时：
(a) 将 is_held() 降级为纯本地持有标志 + 显式 touch 时间戳校验；
(b) 在租约持有路径显式声明 touch() checkpoint 契约（最长间隔 < lease_ttl_s·0.5）；
(c) reviewer_jobs 的孤儿判定统一锁定 wall-clock 并共用单一纯函数。

Target: (1) workspace_lease.py 删除 probe_peer/_probe_posix/_probe_windows/_verify_disk_nonce_match、
PeerLiveness、LeaseHeartbeatThread 及 start/stop_heartbeat_thread、heartbeat_healthy；(2) acquire_or_probe
接管逻辑改为纯 TTL 超时判定 + generation CAS 递增；(3) is_held() 去除心跳时代新鲜度假设，改为本地标志
（保留 generation/boot_nonce CAS 语义）；(4) reviewer_jobs.py 的 _make_liveness_probe 与 reconcile_on_load
统一改用 wall-clock TTL 判定并共用抽出的 is_record_orphaned() 纯函数；(5) 新增崩溃回收与符号消除专项测试。
```

#### 【防御与边缘校验】
- **C-2 generation CAS 绝对保留**：`touch()` 中 `disk_gen != self._generation` 校验不变，僵尸进程过期写被拒。
- **owner_boot_nonce 保留**：`touch()` 仍比对 `disk_nonce != self._boot_nonce`，防 PID 复用。
- **is_held() 语义纠偏（Reviewer R1 修正）**：删除 0.8·TTL 内嵌新鲜度判定，否则长任务将自失活——此为核心修正点，DoD 必测。
- **touch checkpoint 契约**：持有者可安全保留租约的最长无 touch 间隔 = `lease_ttl_s * 0.5`；调用方（reviewer_jobs 持有路径）若跨越该间隔必须显式 `touch()`；若无法保证，须显式抬升 `lease_ttl_s` 并在任务单声明上界。
- **时钟防护边界**：单机 A1 下时钟回拨 → 保守判"未超时"（fail-closed，拒绝接管）；**时钟前跳** → 可能提前夺权，属已知局限，须在 README 与本任务单明确登记（不新增防护代码，避免过度设计）。
- **reviewer_jobs 单 SSOT**：`_make_liveness_probe` 与 `reconcile_on_load` 必须共用 `is_record_orphaned()` 纯函数，TTL 从单一来源读取，禁止两套判活路径。
- **时钟域锁定**：孤儿判定统一使用 wall-clock（`updated_wall_utc`），禁止跨进程使用 `updated_monotonic`。
- **step07 前提约束**：本步删除嗅探后，step07 的 `reclaim_stale_task` 迁移必须仅依赖 TTL + generation CAS 路径，不得假设嗅探可用。
- **import 清理闭环**：`threading`/`sys` 删除前须静态确认无其他使用方（不得留"需确认"悬置）。
