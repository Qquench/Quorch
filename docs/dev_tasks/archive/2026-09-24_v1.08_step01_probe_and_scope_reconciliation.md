#### 【缺陷根因与修改目标】
```
【根因分析】
当前一级文件防线仅在 Antigravity 宿主内通过 PreToolUse 钩子拦截。当外部执行器（Codex CLI、Claude Code）接入时，宿主缺失 PreToolUse 钩子，模型能随意写入未报备源码。同时，检出时缺乏快照记录，任务完成时无法区分哪些改动属于当前任务、哪些改动是工作区遗留污染，造成白名单管控在外部宿主侧物理失效。

【修改目标】
1. 在 manifest.py 中扩展检出基线快照（Baseline Snapshot）机制：在 dev_tasks_checkout 时记录当前工作区受管文件的指纹映射（inode, mtime_ns, size, digest）与 Git HEAD commit；

3. 在 state_machine.py 的 complete 与 escalate 流转前调用对账；若存在白名单外越界改动，直接物理熔断拒绝跃迁并报错提示；
4. 编写 test_external_runner_scope_reconciliation.py 断言越界熔断与白名单合法放行。
```

#### 【分步改造指引】
1. 在 `manifest.py` 中定义 `FileFingerprint`、`BaselineSnapshot` 与 `ReconciliationReport` 数据结构；
2. 实现 `capture_baseline`：遍历工作区受管目录，收集文件元数据，生成不可篡改的 `snapshot_digest` 并保存在 `.agents/.quorch/baselines/<task_id>.json`；
3. 实现 `reconcile_workspace_against_whitelist`：
   - 快速路径：若文件 `inode + mtime_ns + size` 完全一致，判定无漂移并计入 `fast_path_hits`；
   - 慢速路径：若元数据不一致，计算当前 SHA-256 并与基线比对；
   - 比对变更文件集合是否为 `whitelist_paths` 与 `unmanaged_patterns` 的子集；
   - 超出 50ms 预算时短路返回 `verdict='degraded'`；
4. 在 `state_machine.py` 的 `transition_task` 中，对 `STATUS_COMPLETED` 与 `STATUS_REWORK` 跃迁注入对账前置校验，违规时抛出 `ScopeViolationError` 阻断流转；
5. 编写 `test_external_runner_scope_reconciliation.py`，模拟外部 CLI 越界改写源码触发拒绝、白名单内修改正常放行、超预算降级安全处理；
6. 跑测确保全绿。

#### 【防御与边缘校验】
- 纯函数不变量：`reconcile_workspace_against_whitelist` 不得产生任何写系统调用，绝不触碰被观测文件；
- 降级安全不变量：若对账返回 `verdict='degraded'`，必须触发阻断或交还人工确认，严禁静默放行；
- 容错排除：对账算法必须严格排除 `unmanaged_paths`（如 `docs/**` 与 `*.md`），防止合法文档修改被误拦截；

```
【根因分析】

【修改目标】
1. 在 path_guard.py 中提取权威的路径规范化与比较键生成纯函数（canonicalize_path、comparison_key）；
2. 实现基于规范化键的白名单子集判定 is_within_whitelist 与 check_subset；
3. 支持平台感知的大小写折叠：Windows 下自动采用 casefold 消除盘符与文件名大小写分叉，Linux 下保持大小写严格敏感；
4. 保证工作树对账逻辑与 PreToolUse 钩子、Git Pre-commit 守卫在判定内核上 100% 算法同构。
```
