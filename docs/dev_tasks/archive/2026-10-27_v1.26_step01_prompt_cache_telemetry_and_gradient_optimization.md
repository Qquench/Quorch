### 任务 1.1 ✔️ 已完成 — 修复 acomplete 流式调用 Usage 解析与全量遥测审计落盘

#### 【涉及文件】
```
[MODIFY] plugins/quench-dev-tasks/server/reviewer_engine.py
[NEW] plugins/quench-dev-tasks/server/tests/test_acomplete_telemetry.py
```

#### 【缺陷根因与修改目标】
```
根因：(1) 在 reviewer_engine.py 的 complete(stream=True) 方法中，SSE 解析循环遇到 choices 为空时直接 continue，而 OpenAI/DeepSeek 标准流式尾包恰恰是在 choices 为空时携带 final usage，导致 stream 模式无法捕获实际的 prompt_tokens 与 cached_tokens；(2) 由此导致 acomplete 落在 cache_telemetry.jsonl 中的记录全部显示 prompt_tokens=0, cached_tokens=0, usage_available=false，形成 1.7% 的统计盲区。
目标：(1) 在 complete(stream=True) 的 SSE 循环中正确提取 choices 为空时的 usage 字典；(2) 确保 acomplete 正确捕获并沉淀包含真实 token 与 hit_ratio 的 CacheTelemetryRecord；(3) 编写独立回归测试 test_acomplete_telemetry.py。
```

#### 【目标签名与类型契约】
```
ReviewerClient.complete(messages, stream=True, ...) -> Dict[str, Any]（其返回字典中的 usage 包含 prompt_tokens 与 prompt_cache_hit_tokens）
CacheTelemetryRecord(prompt_tokens=..., cached_tokens=..., usage_available=True)
```

#### 【分步改造指引】
1. 修改 plugins/quench-dev-tasks/server/reviewer_engine.py 中 ReviewerClient.complete 的 SSE 响应解析：在判断 if not choices 之前先检查并暂存 chunk_json.get('usage')，并在流结束时将其实际 token 计数合并至最终返回字典。
2. 确保 acomplete 提取 usage 能够正确获取 prompt_tokens 与 cached_tokens 并据此计算精确 hit_ratio 与 usage_available。
3. 新增 plugins/quench-dev-tasks/server/tests/test_acomplete_telemetry.py，模拟含有 choices=[] 延迟 usage 尾包的 SSE 流，验证 complete 与 acomplete 能正确解析 usage 并通过 RollingJsonlTelemetrySink 落盘。
4. 运行 DoD 命令验证通过。

#### 【防御与边缘校验】
Choices 为空但 Usage 存在防跳过：在 SSE stream 处理循环中，当 choices 为空时若存在 usage 键，必须提取真实 prompt_tokens 与 cached_tokens，不得直接 continue 丢弃
非流式与流式分支统一提取：确保 complete 方法在 stream=True 与 stream=False 两种模式下均能向外返回包含 prompt_tokens 与 cached_tokens 的完备 usage dict
无使用量异常防御：若模型提供商未返回 usage，保持默认 0 并置 usage_available=False，绝不抛出未捕获异常

#### 【DoD 验证命令】
```bash
pytest plugins/quench-dev-tasks/server/tests/test_acomplete_telemetry.py plugins/quench-dev-tasks/server/tests/test_cache_telemetry.py -v
```
