#### 【缺陷根因与修改目标】
```
根因分析：在代码审查与推演中，多文件 AST 切片探索（explore_code_slices）与上下文解析（resolve_context_files）目前依赖输入路径序列及内部探索 BFS 遍历顺序，切片集合未在生成源头与组装环节实施绝对确定性排序（Canonical Ordering）；此外，在多轮推演与多 Hop 探索中，切片文本重复进行字符串格式化与切片提取，且换行符未统一转为 LF，微小的空白符或排序扰动将导致 Layer 2 缓存指纹与 KV Cache 彻底失效。\n改进目标：在 code_explorer.py 与 consultation.py / reviewer_engine.py 中建立规范化的切片确定性排序律：按 (rel_path.replace('\\', '/'), start_line, end_line) 进行全局字典序排列；在 consultation.py 多轮交互中统一 \\r\\n -> \\n 并规范化代码切片块的组装；建立切片格式化与哈希驻留机制；新增严密测试集 test_ast_slice_cache_determinism.py。
```

#### 【目标签名与类型契约】
```
explore_code_slices(workspace_root: str, seed_files: Sequence[str], max_hops: int = 1, deadline_seconds: float = DEFAULT_DEADLINE_SECONDS) -> ExploreResult: result.files 严格按 (sf.rel_path.replace('\\', '/'), sf.symbols[0].lineno if sf.symbols else 0) 升序稳定排列。
resolve_context_files(...) -> tuple[list[CodeSlice], list[str], bool]: 返回的 slices 严格按 (s.rel_path.replace('\\', '/'), s.start_line, s.end_line) 升序排列，且所有切片内容强制 \\r\\n -> \\n 规范化。
PromptAssembler.format_slice_block(slice: CodeSlice) -> str: 提供统一的代码块格式化纯函数，保证在单轮与多轮 Hop 中生成的切片 markdown 代码块字节级一致。
```

步骤 2: 在 consultation.py 的 resolve_context_files 中，对提取的 slices 进行 (rel_path, start_line, end_line) 稳定排序，并强制 \\r\\n -> \\n。
