#### 【缺陷根因与修改目标】
```
根因分析：在 v1.25 双模编排拓扑与全自动流水线落地后，预调用钩子 context_injector.py 仍保留了旧版本硬编码提示词：只要检测到 pending_count > 0，就无视当前运行时状态直接下发“双模型交接是默认流程，起草完成或面对未审任务时，必须主动向用户输出规范的任务交接卡并停下”。这与 harness_next_action 的全自动连续流转（PROPOSE -> REVIEW -> CONFIRM -> CHECKOUT -> COMPLETE -> ARCHIVE）发生强烈的指令对抗与语义撕裂，导致主模型频繁被 Hook 误导而过早刹车中断流水线；此外，dev-tasks-discipline.md 中的停机触发时机也尚未与 AGENTS.md §6 对齐。\n改进目标：重构 context_injector.py，引入对 Autopilot 流水线接力状态的探查能力，在连续接力态（PROPOSE, REVIEW, CONFIRM, CHECKOUT, DISPATCH_RUNNER, SYNC_DOCS, ARCHIVE, NEXT_BATCH_PROPOSE）下，坚决抑制遗留交接刹车卡，注入正向接力指引；将 dev-tasks-discipline.md 中的停机规则与 AGENTS.md §6 完全对齐；新增单元测试覆盖各类流水线状态下的 Hook 注入行为。
```

#### 【目标签名与类型契约】
```
context_injector.py 主入口逻辑：从 quench_stack.yaml 与状态机探查 harness_next_action，在接力态下生成接力引导提示词，仅在终态或断点停靠态生成总结交付提示词。
```

#### 【分步改造指引】
步骤 1: 重构 context_injector.py，彻底清除硬编码的旧版停靠与交接卡强提示，加入对编排模式与接力状态的探查逻辑。
步骤 2: 同步修订 plugins/quench-dev-tasks/rules/dev-tasks-discipline.md §4，明确在 Autopilot 流水线全自动流转期间禁止非预期停靠，仅在终态 (ROADMAP_DONE)、阻塞 (BLOCKED) 或断点设置点输出停机交付卡。
步骤 3: 编写 plugins/quench-dev-tasks/server/tests/test_context_injector_autopilot_harness.py，模拟待确认任务在 Autopilot 接力态与终态下的 Hook 响应，确保 100% 绿色通过。
