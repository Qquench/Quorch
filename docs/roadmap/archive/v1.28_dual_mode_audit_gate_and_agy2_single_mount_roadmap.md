## 0. 背景与演进动因（Verdict & Motivation）

结合 Gemini 4（主会话旗舰推理模型无法由轻量级会话反向升权唤起，推荐以显式 `inverted` 委派模式担任 `reviewer_orchestrator`）与 Antigravity 2.0 原生插件与 Hook 体系升级，当前仓库存在四项影响双模零摩擦运转的核心契约缺口：

1. **显式委派模式（Explicit `inverted`）与 `_check_audit_gate` 的信任错位**：
   当工作区显式切换至 `effective_mode == "inverted"` 且 `mode_source == "explicit"` 时，主会话本身即为用户指定的旗舰 `reviewer_orchestrator`（`effective_reviewer_channel = None`），不再调用外部 HTTP Reviewer API。然而 `server.py` 中 `_check_audit_gate` 仍无条件索要 `.agents/logs/reviewer/verdicts.jsonl` 中的匹配的外部记录，在缺省记录时触发 `no_matching_record` 硬阻断 `dev_tasks_confirm`。
2. **`POLL_WAIT_MAX_S_HARD_CEILING` 魔法数字散落与 Reviewer `jobs/` 终态产物无界堆积**：
   `server.py` 的 `_clamp_wait` 仍内联硬编码 `25.0`，尚未提取至 `tool_surface_constants.py` SSOT；同时 `ReviewerJobSupervisor.gc_terminal_jobs()` 虽已实现，但未在 `submit()`、`cancel()` 与 `reconcile_on_load()` 生命周期钩子中机会式触发，导致 `.agents/logs/reviewer/jobs/<ws_hash>/<session_id>/` 下的终态 `.record.json` 与 `.result.json` 长期累积。
3. **Antigravity 2.0 双源插件重复挂载与 `PreToolUse` / `Stop` Hook 契约代差**：
   - `config_sync.py` 在 `.agents/plugins.json` 已挂载本地插件时仍向 `<workspace>/.agents/` 镜像生成 `mcp_config.json` 与 `hooks.json`，导致 MCP 工具集出现 `quench-dev-tasks` 与 `quench-dev-tasks_quench-dev-tasks` 双重注册及 Hook 双重触发；
   - Antigravity 2.0 将文件编辑原语升级为 `edit_file(Path, Target, Replacement)` 与 `write_file(Path, Content, Append, Overwrite)`，旧版 `hooks.json.template` 仅匹配 `replace_file_content|multi_replace_file_content|write_to_file` 且 `file_scope_guard.py` 仅读取 `TargetFile`，导致新版工具逃逸 `PreToolUse` 实时白名单与状态机防篡改拦截；
   - 缺少受控熔断的 `Stop` Hook 在 Autopilot 连续接力态（`REVIEW` / `CONFIRM` / `CHECKOUT` / `DISPATCH_RUNNER` / `ARCHIVE` / `NEXT_BATCH_PROPOSE`）对 `NO_TOOL_CALL` 提前停机做单次自动续跑兜底。
4. **Antigravity 2.0 原生插件规则入口（`plugins/quench-dev-tasks/rules/AGENTS.md`）缺位**：
   Antigravity 2.0 插件规范推荐在插件 `rules/AGENTS.md` 提供无 YAML frontmatter 的纯 Markdown 常驻规则入口；当前插件目录仅有 `templates/AGENTS.md` 供脚手架渲染，缺少原生挂载即生效且与根 `AGENTS.md` 保持 `QUENCH-CORE-INVARIANTS` 逐字同步的 `rules/AGENTS.md`。

## 1. 架构目标与改造边界（Architecture Objectives）

1. **双模 `AuditGate` 精确对齐（显式委派放行 + `auto_fallback` 严防降级绕过）**：
   - 仅当 `snap.effective_mode == "inverted" and snap.mode_source == "explicit"`，且审计日志缺失（`log_missing`）或无匹配外部记录（`matching_rec is None`）时，以新增原因码 `"explicit_inverted_orchestrator"` 放行；
   - 若外部账本中已存在匹配记录但判定为 `record_rework`、`record_unparsable`、`record_stale` 等异常，依然严格按原阶梯拦截；`mode_source == "auto_fallback"` 绝不享受免审放行。
2. **常量 SSOT 收敛与机会式终态作业 GC**：
   - 在 `tool_surface_constants.py` 声明 `POLL_WAIT_MAX_S_HARD_CEILING: Final[float] = 25.0` 并由 `server._clamp_wait` 唯一引用；
   - 在 `ReviewerJobSupervisor` 的 `submit`、`cancel`、`reconcile_on_load` 中接入机会式 `gc_terminal_jobs()` 及空会话子目录回收，严格保持 `REVIEWER_TERMINAL_LOG_RETENTION (40) > REVIEWER_LOG_QUOTA_KEEP (20)` 的流式日志配额契约不变。
3. **单源插件自愈、`PreToolUse` 新工具全覆盖与单次熔断 `Stop` Hook**：
   - `config_sync.py` 自动检测 `<workspace>/.agents/plugins.json` 是否已挂载当前插件：若已挂载则仅自愈插件目录配置，并安全剥离/清理 `<workspace>/.agents/{hooks.json, mcp_config.json}` 中的冗余挂载（保留第三方 MCP Server）；无 `plugins.json` 的独立工作区维持原有双写行为 100% 兼容；
   - `hooks.json.template` 与 `file_scope_guard.py` 完整覆盖 `edit_file`、`write_file`、`delete_file`、`run_command` 及旧版编辑工具；
   - `context_injector.py` 与 `hooks.json.template` 增加 `Stop` Hook 分支：仅在 `terminationReason == "NO_TOOL_CALL" and fullyIdle is True`、存在活跃任务单、`stop_at == "none"` 且处于非终态接力动作时，基于 `(conversationId, action, task_file)` 状态指纹触发至多 1 次 `{"decision": "continue", "reason": "..."}` 熔断续跑，杜绝子代理或普通问答死循环。
4. **插件级 `rules/AGENTS.md` 三端同步门禁与文档账本毕业**：
   - 建立纯 Markdown（无 YAML frontmatter、`<= 120` 行）的 `plugins/quench-dev-tasks/rules/AGENTS.md`，纳入 `test_agents_md_sync.py` 三端哨兵块逐字一致性校验，并完成架构文档与 `future_roadmap_ideas.md` 毕业归档。
