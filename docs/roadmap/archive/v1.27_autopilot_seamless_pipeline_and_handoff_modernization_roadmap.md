## 0. 背景与演进动因（Verdict & Motivation）

在全自动开发流程中，出现主模型在提出任务后突然抛出【Quench 任务交接卡】并提前结束回合等待人类用户手动开新会话调 Reviewer 的问题。
经排查，虽然 v1.25/v1.26 已实现并加固了 `harness_next_action` 接力棒与 Hook 层提醒，但在服务端核心工具与规约定义中仍残存多处早期版本（v1.07/v1.08）的手工多会话交接遗留逻辑：

1. **`server.py` 中 `dev_tasks_checkout` 的过时指令残留**：
   当已确认任务队列为空且存在待终审或返工任务时，`dev_tasks_checkout` 硬编码返回 `"instruction"` 要求“输出【Quench 任务交接卡】，引导用户在新会话切换至自选的高阶架构审查模型进行审查修订”，直接导致主模型接收到打断指令而停机。
2. **`server.py` 中 `dev_tasks_escalate` 的停机指令残留**：
   硬编码命令模型“立即停止后续代码修改！向用户输出【Quench 任务交接卡】，等待用户在新会话中由高阶架构审查模型完成审查修订”。
3. **`reporting.py` 中 `render_handoff_card` 步骤固化**：
   交接卡正文硬编码为“点击 `+` 开启新的纯净会话”、“切换至预先分配的高阶架构审查模型”，未适配当前已支持的 Reviewer API 自动审查与子 Agent 模式。
4. **规约与入口文档中的旧范式表述**：
   `dev-tasks-discipline.md` §4、`dev-tasks-workflow/SKILL.md` 与 `AGENTS.md` §1 中未清晰阐明：在 Standard / Inverted Autopilot 模式下，Reviewer 审查默认通过 `dev_reviewer_submit` 或子 Agent 自动在带内推进，严禁主动中断流程要求开发者开新会话。

## 1. 架构目标与改造边界（Architecture Objectives）

1. **纯自动化带内接力为一等公民**：
   在 Standard 模式（配置 Reviewer API）及 Inverted 模式下，任务从 Propose 到 Review 均为带内连续执行，严禁工具返回值与提示词下发“开新会话交接”等刹车指令。
2. **多模式自适应交接卡**：
   `render_handoff_card` 与 `_resolve_handoff_envelope` 升级为策略感知（Strategy-Aware）：优先指引自动化 `dev_reviewer_submit` / 子 Agent 审查；仅在 `mode == "manual"` 或引擎完全离线不可用时，才降级提供手工开新会话指引。
3. **彻底对齐入口卡与纪律契约**：
   更新 `AGENTS.md`、`dev-tasks-discipline.md` 与 `dev-tasks-workflow/SKILL.md`，使入口契约、规约、服务端工具三位一体，杜绝任何相互矛盾的提示词。
