## 1. Executive Summary & Root Cause (背景与根因)

### 1.1 问题背景 (Problem Statement)
在 `inverted`（委派/反转）编排模式下，主会话担任高阶 `reviewer_orchestrator` 角色，负责架构规划、规约把关与任务分派，而具体的代码施工（`[QUENCH-DISPATCH: RUNNER]`）与广度代码探查（`[QUENCH-DISPATCH: RESEARCH]`）应委派给宿主子代理执行。

然而在实际运行中（例如在 Antigravity 宿主下由高阶主模型发起委派），主会话唤起子代理时往往默认使用了 `inherit`（直接继承主会话的前沿推理大模型），而非宿主提供的轻量/快速执行档位，背离了倒置模式“主会话高阶把关 + 子代理轻量执行”的初衷，需要用户额外口头纠正。

### 1.2 为什么不能把 `"flash"` / `"pro"` 等档位名写死 (Why Tier-Literal Neutrality Matters Beyond Vendor Neutrality)
在 **INV-5（核心模块零厂商字面量）** 之外，还存在一个更现实的工程约束：**模型代际与宿主档位映射正在快速演进**。
- 新一代模型（如 4 代体系）已不再沿用传统的 `flash` / `pro` 命名；
- 宿主平台自身也会在后台动态重映射子代理档位（例如将传统轻量档位别名路由到新一代高阶/中阶模型，或随时调整档位列表与别名语义）。

因此，**将 `"flash"`、`"pro"` 或具体模型代号写死在环境配置、服务端核心模块或常驻治理规则中是脆弱且易过时的**。正确做法是以**能力与成本语义（semantic capability/cost tier）**表达路由意图——例如 `"prefer lightweight/fast tier over inheriting main session model"`——让主会话在调用宿主 `invoke_subagent`（或其他跨宿主委派原语）时，**动态从当前宿主实际提供的子代理选项中选择轻量/快速执行档位**，而仅将 `runner_subagent_model_hint` 保留为“用户按需显式覆写”的可选透传字段。

### 1.3 根因解构 (Verified Codebase Gaps)
经代码核查，当前行为并非操作遗漏，而是仓库在以下四处存在断层：
1. **宿主工具默认契约向 `inherit` 倾斜**：
   - 宿主 `invoke_subagent` 的 `Model` 参数说明默认为 `'inherit'`（`"Default to 'inherit' unless the user explicitly requests a different model"`）。若 Quench 规则与运行时指令未显式给出相反引导，主会话会按工具默认说明传 `'inherit'`。
2. **`runner_subagent_model_hint` 缺省为 `null`，且缺乏轻量档位语义兜底**：
   - `plugins/quench-dev-tasks/server/runtime_mode.py` 中 `RuntimeModeState.runner_subagent_model_hint` 默认为 `None`；
   - `generate_session_role_contract`（`runtime_mode.py`）在 `inverted` 模式下仅描述 `"执行施工委托给 Runner 子 Agent"`，当 `runner_subagent_model_hint` 为 `None` 时未表达“优先选择轻量/快速执行档位、勿默认继承主模型”的策略。
3. **`DISPATCH_RUNNER` 决策指令与 Hook 接力棒未传递档位语义**：
   - `plugins/quench-dev-tasks/server/autopilot_harness.py::compute_next_action` 在生成 `DISPATCH_RUNNER` 时，透传了 `model_hint=runner_subagent_model_hint`，但当 `model_hint` 为 `None` 时，`instruction` 仅说明 `reuse_active` 与 `spawn_fresh` 策略，未附带任何档位偏好提示；
   - `plugins/quench-dev-tasks/server/hooks/context_injector.py::_resolve_harness_baton` 调用 `compute_next_action(...)` 时漏传 `runner_subagent_model_hint=snapshot.runner_subagent_model_hint`。
4. **规则与 Skill 缺失子代理模型档位路由约束**：
   - `AGENTS.md`（及 `plugins/quench-dev-tasks/rules/AGENTS.md`、`plugins/quench-dev-tasks/templates/AGENTS.md`）、`plugins/quench-dev-tasks/rules/dev-tasks-discipline.md`、`plugins/quench-dev-tasks/skills/dev-tasks-workflow/SKILL.md` 目前仅定义了 `[QUENCH-DISPATCH: RUNNER | REVIEWER | RESEARCH]` 信封与“子代理免调 `dev_tasks_status`”，未定义委派时的模型档位选择优先级。

## 2. Objectives & Non-Goals (目标与非目标)

### 2.1 核心目标 (Goals)
1. **全链路厂商与档位字面量中立（Zero Transient Tier Literals）**：
   - 服务端代码、常驻规则（`AGENTS.md` / `dev-tasks-discipline.md`）、Skill（`SKILL.md`）与配置模板中**不硬编码** `"flash"`、`"pro"` 或任何具体厂商/代际模型名；
   - 统一以语义化能力档位表述路由策略：**Runner / Research 子代理优先选用宿主当前可用的轻量/快速执行档位（prefer lightweight/fast tier over inheriting main session model）**，避免无条件继承主会话推理大模型。
2. **明确的两级优先级路由契约**：
   - **Priority 1（显式 Hint 优先）**：若运行态下发了非空的 `runner_subagent_model_hint`（含 `DISPATCH_RUNNER.model_hint` 与 `session_role_contract.runner_subagent_model_hint`），主会话优先按该值匹配宿主子代理模型参数；
   - **Priority 2（语义轻量档位兜底）**：当 `runner_subagent_model_hint` 为 `null`（默认态）时，主会话**禁止默认选择 `inherit`**，应从宿主当前可见的轻量/快速/高性价比子代理档位中择优分派；仅当宿主无任何更轻档位可选，或子代理因推理复杂度明确失败需升级重跑时，才回退为 `inherit` 或更高档位。
   - **对称反向约束（`standard` + `host_subagent` 审查通道）**：在标准模式下通过 `[QUENCH-DISPATCH: REVIEWER]` 委派审查子代理时，优先选用高阶/强推理档位，而非轻量档位。
3. **Runtime 契约、Autopilot 指令与 Hook Baton 三端对齐**：
   - 补齐 `runtime_mode.py::generate_session_role_contract`、`autopilot_harness.py::compute_next_action` 与 `hooks/context_injector.py::_resolve_harness_baton` 的档位语义与 `runner_subagent_model_hint` 透传，并严守 `RESPONSE_BUDGET_BYTES`（`dev_tasks_status` ≤ 2048B）与 `MAX_TOOL_SCHEMA_BYTES` 预算。
4. **保持既有治理门禁 100% 绿灯**：
   - 严守 `test_agents_md_sync.py`（三端哨兵块逐字同步 + ≤ 120 行预算）、`test_doc_contract_hygiene.py`（宿主中立抽象动词）、`test_no_vendor_literals_in_core.py`（INV-5）与 `test_response_budget_ssot.py`。

### 2.2 显式非目标 (Non-Goals)
- **不在核心模块或默认规则中引入任何模型/档位硬编码映射表**（例如不维护 `"antigravity": "flash"` 等易过时常量）；
- **默认不扩充 `dev_tasks_status` MCP 工具参数签名**：Batch 1 先验证纯语义提示词 + 运行态信号是否足以让宿主主模型稳定避开 `inherit`；仅在实测仍需便捷运行时覆写或每仓库固定覆写时，再按 Batch 2 评估引入可选配置通道（避免无谓增加工具 Schema 字节数，维护 `v1.31` 瘦身成果）。

## 3. Architecture & Core Specifications (架构与契约规约)

### 3.1 委派档位路由决策矩阵 (Delegation Tier Routing Matrix)

| 派发信封 / 场景 | 目标子代理职责 | `runner_subagent_model_hint` 非空 | `runner_subagent_model_hint` 为 `null`（默认） | 允许升级/回退 `inherit` 条件 |
| :--- | :--- | :--- | :--- | :--- |
| `[QUENCH-DISPATCH: RUNNER]` (`inverted`) | 按既定六大字段规约实施代码与跑测 | 使用 `model_hint` 指定档位 | **优先选择宿主可用的轻量/快速执行档位**，禁止默认 `inherit` | 宿主无轻量档位，或轻量档位因复杂逻辑连续失败需升级 |
| `[QUENCH-DISPATCH: RESEARCH]` (`inverted`) | 只读检索、AST/行号定位、返回探查简报 | 使用 `model_hint`（或同级轻量档位） | **优先选择宿主可用的轻量/快速执行档位**，禁止默认 `inherit` | 宿主无轻量档位 |
| `[QUENCH-DISPATCH: REVIEWER]` (`standard` + `host_subagent`) | 架构审查、反锚定挑刺与规约评审 | 不适用（非 Runner Hint 作用域） | **优先选择宿主可用的前沿/强推理档位**（或 `inherit` 若主模型本身为高阶模型） | 宿主无独立强推理档位 |

### 3.2 文档与规则分层改动契约 (Layered Doc & Rule Contract)
严格遵守 `Rules > Skills > AGENTS.md` 优先级以及 `AGENTS.md` ≤ 120 行、三端哨兵同步契约：
1. **`plugins/quench-dev-tasks/rules/dev-tasks-discipline.md`**（权威规范层）：
   - 在合适章节（如 `§4` 或扩展为子代理委派纪律条目）写入完整的厂商中立档位路由规则（含 Priority 1/2、`RUNNER`/`RESEARCH` 优先轻量档位、`REVIEWER` 优先强推理档位、禁止硬编码瞬态模型名、失败升级条件）。
2. **`plugins/quench-dev-tasks/skills/dev-tasks-workflow/SKILL.md`**（操作手册层）：
   - 在 `§1 Inverted Dual-Layer Code Exploration` 与 `Runner Subagent Reuse vs. Fresh Spawn Policy` 中补充操作性指引：发起 `[QUENCH-DISPATCH: RESEARCH]` 与 `[QUENCH-DISPATCH: RUNNER]` 时，显式从宿主子代理模型选项中选择轻量/快速档位（或遵循 `model_hint`），而非依赖宿主默认 `inherit`。
3. **`AGENTS.md`、`plugins/quench-dev-tasks/rules/AGENTS.md`、`plugins/quench-dev-tasks/templates/AGENTS.md`**（入口路由卡层）：
   - 在 `§4. Subagent Protocol & Envelope Dispatch`（及 `templates/AGENTS.md` 对应精简提示位）追加不超过 1~2 行的紧凑路由原则：
     - `Delegation Tier`: For `[QUENCH-DISPATCH: RUNNER | RESEARCH]`, honor `runner_subagent_model_hint` if set; otherwise prefer a lightweight/fast tier over inheriting the main session model.
   - 保持 `<!-- QUENCH-CORE-INVARIANTS:BEGIN -->` / `END` 三端完全一致，且三份文件总行数均严格控制在 `<= 120` 行内；注意 `templates/AGENTS.md` 当前结构为 `§1..§5`，需确认新增位置不破坏 `test_agents_md_sync.py` 与 `test_agents_md_template.py`。

### 3.3 服务端与 Hook 信号对齐 (Server & Hook Signal Alignment)
1. **`plugins/quench-dev-tasks/server/runtime_mode.py` (`generate_session_role_contract`)**：
   - 在 `effective_mode == "inverted"` 分支的 `primary_guidelines` 中补充一条中立指引：
     - 当 `runner_subagent_model_hint` 为空时：`"委派 Runner / Research 子代理时优先选用宿主可用的轻量/快速执行档位（prefer lightweight/fast tier over inheriting main session model），勿默认继承主会话模型。"`
     - 当 `runner_subagent_model_hint` 非空时：`f"委派 Runner / Research 子代理优先使用指定档位提示: {runner_subagent_model_hint}（若宿主不可用则回退轻量执行档位）。"`
2. **`plugins/quench-dev-tasks/server/autopilot_harness.py` (`compute_next_action`)**：
   - 在 `DISPATCH_RUNNER`（`in_progress_tasks` 与 `confirmed_tasks` 两个分支）构造 `instruction` 时附加紧凑档位提示（严格控制字节增量，确保 compact `dev_tasks_status` 远低于 `2048B`）：
     - 若 `runner_subagent_model_hint` 非空：附带 `model_hint={runner_subagent_model_hint}`；
     - 若 `runner_subagent_model_hint` 为 `None`：附带 `prefer lightweight/fast tier, not inherit / 优先轻量快速档位，勿默认继承主模型`。
3. **`plugins/quench-dev-tasks/server/hooks/context_injector.py` (`_resolve_harness_baton`)**：
   - 调用 `compute_next_action(...)` 时补传 `runner_subagent_model_hint=snapshot.runner_subagent_model_hint`，保证 Hook 注入的接力提醒与 MCP 返回完全同源。

### 3.4 可选显式覆写通道（Batch 2：仅在语义路由仍需人工锁档时启用）
若实测中发现不同宿主或特定团队仍需要声明式锁定 `runner_subagent_model_hint`（且不想手改 `.agents/.quench_runtime_mode.json`），优先采用**零 MCP Schema 膨胀方案**：
- **Option A（推荐，零 Tool Schema 膨胀）**：在 `project_config.py`（`.agents/quench_stack.yaml` 与 `.gitignored` 的 `.agents/quench_stack.local.yaml`）中支持可选键 `orchestration.runner_subagent_model_hint: null`。优先级定义为：
  `.agents/.quench_runtime_mode.json` 显式值 > `quench_stack.local.yaml` > `quench_stack.yaml` > `None`。
  此方案不修改 `dev_tasks_status` 参数列表，完全零影响 `MAX_TOOL_SCHEMA_BYTES` 与 `ide_tool_schemas.json`。
- **Option B（可选动态 MCP 切换）**：仅当确有会话内动态热切换 Hint 的诉求时，再评估为 `dev_tasks_status` 增加 `runner_subagent_model_hint: Optional[str] = None` 并同步 `docs/architecture/ide_tool_schemas.json`，且必须通过 `measure_tool_schema_bytes <= WARN_TOOL_SCHEMA_BYTES (900B)` 门禁。
