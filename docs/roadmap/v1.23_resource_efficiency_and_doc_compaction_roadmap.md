## 第 1 章 核心宗旨、双战线划分与奥卡姆剃刀重构

### 1.1 背景与痛点根因

在 v1.20~v1.22 的演进三部曲中，系统成功在**执行轴与输出轴**达成了扎实的瘦身：
- 全量回归耗时从 114s 降至 61.36s（-46.2%），测试 I/O 放大被消除（35s -> 2.96s），Tier-1 快反馈稳定在 ~2.02s；
- C2 心跳契约（单行文本）消除轮询弹窗与 JSON 杂散污染；
- C3 交付卡契约（<= 5 行）杜绝在 Chat 中倾倒巨型 Diff 与删除账本。

然而，在**输入轴、认知轴与历史包袱**上，系统的膨胀与 Token 浪费依然存在：
1. **常驻输入常数税沉重**：每轮会话中，长篇纪律规则（约 12KB）、代理入口卡、各技能说明全量注入，随会话轮次线性消耗全价 Token；
2. **门禁结构严重不对称**：现存门禁均为防止删除的单向门禁（Zero-Delete 与悬空引用防线）。全仓只有“防删刹车”，没有“促缩油门”，没有任何机制防止文档或测试无节制膨胀；
3. **化石门禁倒逼假性资产**：版本专用测试（如 646 行的 v1.22 证据消费门禁）强制校验两份 Markdown 表格的内容双向对齐，并硬编码锁定工具面快照的 SHA256 哈希。**测试在测历史而非测行为，反向锁死工具面的正常演化，导致历史台账无法归档**；
4. **历史开发遗留物堆积**：仓库中充斥着早期版本开发专用的一次性台账、冻结清单、过渡测试、早期宏大规划草案与无实质操作的 MCP 包装垫片，对于工具的实际运行徒增认知与检索负荷。

### 1.2 双战线架构划分原则 (Dual-Track Architecture)

根据架构审查模型的深度审计，严格切分两条性质完全不同的战线：

| 战线 | 治理对象 | 风险性质 | 处置策略 |
|---|---|---|---|
| **战线 A：历史版本化石退役 (主攻目标)** | 版本账本 / 冻结基线 / 快照 / 历史草案 / 化石门禁测试 / 一次性脚本 | 审计链断裂 + CI 假红（无运行时破坏风险） | **纳入 v1.23 核心范围**：解耦自锁门禁，历史产物移入归档排除域，化石测试安全退役 |
| **战线 B：代码符号瘦身 (独立任务)** | 潜在删除清单中的 138 个未引用符号、通用 CLI 适配器等 | 运行时动态反射盲区、中立性破坏 | **严禁在 v1.23 批量误删**，作为后续独立重构任务，逐符号通过动态调用排查后独立落地 |

## 第 3 章 关键技术契约

### 3.1 历史化石解耦与自锁解锁契约
- **化石门禁解耦原则**：门禁测试只应断言**当前系统行为与通用纯函数**，不得断言**历史文档字节与表格内容**。
- **提取与退役动作**：
  - 将通用纯函数裁决断言（判定 CONFIRMED 需证据、COLLAPSED 需理由）提取为版本无关的独立测试；
  - 彻底退役对特定版本路线图表格、特定 YAML front-matter 的逐字校验；
  - 解锁工具面快照的逐字节硬哈希比对，消除对工具面正常演化的非法阻断。

### 3.2 归档排除域与检索纯净化契约
- **复用既有排除机制**：在配置文件的排除目录配置项中增补：
  - `docs/architecture/archive/**`
  - `docs/roadmap/archive/**`
  - `docs/dev_tasks/**` (含其归档 `archive/**`)
- **零新工具承诺**：归档文件查阅完全复用基础文件读取能力，严禁增加专用查询 MCP 工具。

### 3.3 零元复杂度文档促缩契约
- **既有单测硬断言**：在已有单测（如 rules exporter 相关测试）中新增字典常量断言，限定关键常驻文档大小：
  - 纪律规则正文 <= 9,000 字节（压降约 25%）；
  - 代理入口说明 <= 3,500 字节。
- **机械下沉与行为保留**：
  - 格式匹配、字段命名、文件白名单规范下沉至已有的 schema 校验与 AST 门禁；
  - 反角色扮演、停机上报、只读审查等核心行为准则 100% 保留在规则正文中。

### 3.4 MCP 工具面收敛契约 (17 -> 16)
- **退役纯提示垫片**：咨询直接通道（consult 垫片）仅为早期阻塞模式遗留的跳转指引卡，无实质执行价值，安全退役，MCP 工具面正式收敛至 16 个；
- **检出操作内聚**：任务领单检出在遇到超时僵尸任务时自动执行安全回收，不再强依赖外部模型显式排查回收。

### 3.5 动态性能信封契约 (单向下移 + 双向假红防护)
- **单向动态收敛公式**：
  $$\text{Baseline}_{\text{next}} = \max(\text{TIER2\_ABSOLUTE\_FLOOR\_S}, \min(\text{Baseline}_{\text{prev}}, \text{robust\_estimate}))$$
  $$\text{TIER2\_WARN\_S} = \text{Baseline}_{\text{next}} \times 1.15$$
  $$\text{TIER2\_PANIC\_S} = \text{Baseline}_{\text{next}} \times 1.30$$
  - **安全地板与旧地板区分**：引入 30s 安全地板 (`TIER2_ABSOLUTE_FLOOR_S = 30.0`)，显式区别于已废除的 85s 固定操作地板，防止极限收敛引发无谓抖动；
  - **下行确认**：单次运行 3 采样或连续 3 轮确认 (`RATCHET_CONFIRM_ROUNDS = 3`) 经中位数鲁棒估计量验证后方可单向下移；
  - **双向假红防护**：重试样本不污染基线；上行设置防抖门槛 (`PANIC_DOWNGRADE_STREAK = 2`，运行内连续 2 次超限才硬阻断，单次超限降级 WARN)；
  - 侧车持久化 (`.agents/bench/tier2_baseline.json`) 为可选加固，缺失或损坏时 fail-safe 回退至保守基线。
