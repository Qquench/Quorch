## 第 1 章 核心宪章与调整后需求边界

### 1.1 运行公理（Runtime Axioms，不可协商）

| ID | 公理 | 物理承载 |
|----|------|---------|
| **A1** | 单机、单用户 | 无多租户/分布式共识假设；跨进程仅限本机 |
| **A2** | stdio JSON-RPC 单网关（+ detached reviewer worker） | `server.py` 为唯一 Tier-2 进程；stdout 纯净契约（INV-4） |
| **A3** | 全局单活跃任务 | manifest `filelock` + CAS（INV-1） |
| **A4** | 状态变更仅经 MCP；Markdown 只写输出 | 服务端校验每次跃迁（INV-2） |
| **A5** | 审查只读 + 异构外部通道（禁就地角色扮演） | `assert_read_only_sandbox`（INV-6）+ 降级卡纪律（INV-3） |

> **A1/A3 的精确边界**：单机 ≠ 单进程。reviewer worker 与网关为**不同进程**，因此所有“单机简化”必须保留**跨进程崩溃回收语义**，不得以“反正单机”为由删除回收路径。

### 1.2 交互契约冻结（Frozen Interactive Contracts）

- **C2 心跳行契约（冻结）**：非终态 `dev_reviewer_poll` 默认 `raw_text=True`，返回**严格单行**字符串：  
  `<时间在前> | <Token 在后>`，示例 `[Reviewer thinking: 12.3s | 1,234 tokens]`。
  - 禁止任何杂散 JSON 代码卡片与文件弹出；
  - SSOT 落在 `reviewer_engine.format_heartbeat_line`，必须有**精确正则断言**；
  - 现有 `docs/architecture/README.md §3.3` 示例若为 Token 在前，属历史 SSOT 冲突，须在 step05 内与实现、spec 原子同步。
- **终态直出契约**：终态 poll 返回完整 Markdown 审阅裁决，不受 `raw_text` 影响，避免在工作区弹出巨型 JSON 文件。
- **C3 Runner 完工交付卡契约（冻结）**：执行模型在调用 `dev_tasks_complete` 交付任务后，会话汇报严格遵循**极简 4 行卡（≤5行）**：
  - ① 任务 ID 与流转状态（`[Task ID] ✔️ 已完成`）；
  - ② 涉及文件清单（紧凑单行/列表）；
  - ③ 自动化验证结果（通过用例数与门禁简述）；
  - ④ 版本回滚锚点 Tag 与更新文档指引。
  - **禁令**：严禁在会话正文中二次复诵已写入 roadmap 的删除账本表格、零删除 Token 计数等已由自动化门禁保证的冗长细节。
  - **异常 carve-out**：非全绿 / 降级 / 升级场景禁用交付卡，改走 §4 Handoff Card 或降级卡。
  - **语言镜像**：卡片语言跟随任务/用户语言（L3 契约）。
  - **落地归口**：本交互契约已在 `AGENTS.md` 与 `plugins/quench-dev-tasks/rules/dev-tasks-discipline.md §8` 中**提前全局固化生效**，新会话一律自动执行；step05 保留 L1 spec 与协议的终态校验。
  - **过度工程驳回记录 (P4)**：驳回 `dod_output` 机械结构化改造提议（过度工程，破坏 L1 协议与原生证据真实性，已归口至 `over_engineering_inventory.md`）。

### 1.3 复杂度门禁 G1'（纠偏后语义边界）

- **废除**僵化教条的“MCP 工具数 ≤ 17 硬上限”。
- **替换为 G1' 语义正交门禁**（三条件全满足）：
  1. **通道正交性**：任一工具不得与另一工具共享完全相同的 (参数 schema + 状态跃迁 + 返回契约) 三元组；
  2. **零重复通道**：不存在语义等价、可互相替代的两个工具；
  3. **单机对应**：工具存在性必须能映射到 A1~A5 中至少一条运行公理，否则标记为删除候选。
- **机械代理**：G1' 不依赖人工直觉，以 step01 的 MCP 工具签名快照（`ToolSurface`）为输入，做三元组去重检测；检测结果纳入 `over_engineering_inventory.md`。

#### 1.4.1 段序判定律与提示词奥卡姆剃刀原则（Anti-Over-Engineering Prompting）

- **段序判定律（KV 链式寻址物理）**：  
  KV Cache 依赖严格最长公共前缀。夹在中间的模式协议任何一字节变动，均会导致下游全部代码切片整块 KV 失效（“小段毒化大段”）。  
  **推论律**：当模式协议被剃刀化压缩至 $\le 200$ token 而代码切片典型 $\ge 4\text{k}$ token 时，模式协议**必须尾置**（前缀共享收益高出前置布局约 19%），且尾置天然获得注意力峰值（消除 Lost-in-the-Middle 遗忘）。
- **提示词奥卡姆剃刀（物理下沉原则）**：  
  **凡能被 validator/lint 机械判定的约束（如字段枚举、分类学清单），一律下沉为物理门禁校验，严禁用长篇 Prompt 约束模型**。  
  枚举式长提示词不仅浪费全价 Token，更会诱发“锚定效应”使模型沦为合规填表工具，反而放行虚空靶标并漏报真正隐蔽缺陷。  
  `critique` 等模式仅保留 ≤5 行的纯证伪定位原则（“指认不出位置的一律不写”），以输出限流取代繁琐分类。
- **语言规范**：系统协议与模式提示词一律统一为**纯英文**（English-only），模型输出语言保持跟随用户查询。

### 1.5 审查模式分级与防过度设计门禁（Review Mode Discipline & G-OE'）

为根除红队无界搜索诱发的系统过度设计，推进期调用 Reviewer 必须遵循**场景-模式强绑定矩阵**：

| 研发阶段 | 对应 SOP | 默认模式 | 核心效用函数与纪律约束 |
|---------|---------|---------|---------------------|
| **架构探索期** | 宏观规划 | `brainstorm` | 发散探索多种设计选项，输出可行性对比与最小 PoC 验证实验 |
| **规划与准入** | SOP-2 任务单生成 | `evaluate` | **默认**。必须携带 Roadmap 目标，以 A/B 成本/收益矩阵权衡，严禁单向堆砌防线 |
| **研发中咨询** | SOP-4 执行中答疑 | `evaluate` | **默认**。针对特定实现做权衡；例外使用 `critique` 须提供具体复现场景 |
| **交付与验收** | SOP-5 验收审计 | `audit` | **默认**。只读核对实现与 DoD 契约一致性，严禁新增范围外需求或诱发二次重构 |

> **防过度设计门禁 G-OE'（三条件）**：  
> 1. **预算绑定**：DevTask 必须声明 LoC 预算与涉及文件域白名单，Reviewer 提议不得超出当前 Step 范围；  
> 2. **上下文锚定**：调用 Reviewer 时必须携带当前 Step 的 Roadmap 目标宗旨与边界约束；  
> 3. **超预算归口**：非本 Step 范围的防御性提议，一律仅落盘至 `over_engineering_inventory.md` 作为远期候选，严禁反向绑架当前 DevTask 膨胀。

## 第 3 章 跨会话滚动推进工作流协议（Rolling Execution Protocol）

**总原则**：路线图锁死大方向，DevTask 单步滚动生成与执行；`dev_tasks_status` + manifest 为进度 SSOT，git tag 仅为回滚锚点。

| 阶段 | SOP 动作 | 审查模式 | 执行规范 |
|------|---------|---------|---------|
| **SOP-0 会话基线检查** | 每次新会话首动作 | — | ① `dev_tasks_status` 看全局状态；② `git tag -l 'v1.20-*'` 看已完成锚点；③ `python scripts/asset_inventory.py --check` 确认取证清单未漂移 |
| **SOP-1 定位目标 step** | 依据锚点选择下一个未完成 step | — | 阅读本文对应 §2.x 章节，比对前置依赖是否满足 |
| **SOP-2 生成 DevTask** | 若该 step 无任务单 | 默认 `evaluate` | 必须附带对应 §2.x 目标，由外部 Reviewer 产出六字段 DevTask 标注 `⬜ 待确认`；严禁默认使用 `critique` |
| **SOP-3 确认** | 任务单就绪 | — | `dev_tasks_confirm(action="confirm")` |
| **SOP-4 检出执行** | 确认后 | 默认 `evaluate` | `dev_tasks_checkout(task_id=...)` → `🔨 执行中`；严格遵循【涉及文件】白名单；中途若需架构咨询默认 evaluate |
| **SOP-5 验收** | 执行完成 | 默认 `audit` | 运行该 step 的【DoD 验证命令】+ 九大不变量基线；step04/06/07 额外运行★并发不变量硬门禁★；核对契约禁止增生需求 |
