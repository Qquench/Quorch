# Quench Dev-Orchestrator v1.21 测试门禁归一与套件去放大路线图 (Test Suite Consolidation & De-amplification Roadmap)

> **Document Type**: Milestone Roadmap (Sub-charter for v1.21)  
> **Preceding Milestone**: `docs/roadmap/v1.20_architecture_slimming_roadmap.md` (v1.20 架构去工业化与轻量化瘦身)  
> **Scope**: 专职承接从 v1.20 架构瘦身中解耦剥离的高危测试断言重构与慢测试去放大（TR-1 与 TR-2）。  
> **Authority**: 本文遵循 v1.20 §1.5 G-OE' 超预算归口原则与 Reviewer 权威裁决，建立独立的断言奇偶校验（Parity Proof）验收体系。

---

## 第 1 章 核心宗旨与问题边界

### 1.1 背景与动因

在 v1.20 演进期间，为了确保架构去工业化（删除进程嗅探、后台心跳线程、配置兼容垫片等）不产生任何回归与漏报，各步骤引入了大量的重构期“防复现守门员”断言：
1. **AST 负向防复现门禁分散**：如 `test_lease_symbol_removal.py`、`test_prompt_layout_criterion.py`、`test_touch_outcome_no_truthiness.py` 中的 AST 语法树扫描，每个用例均独立启动全量源码 AST 解析；
2. **全仓静态扫描物理 I/O 放大**：`test_asset_inventory.py` 内部多次对真实工作区全仓进行遍历扫描、AST 提取与 Markdown 渲染，单文件耗时高达 35s+，占全量回归耗时逾 30%；
3. **测试维护认知负荷**：重构完成后，分散的脚手架测试与业务契约测试混杂，增加了长期演进的代码理解成本。

### 1.2 为什么必须与 v1.20 物理隔离？

根据 Reviewer 评估裁决：
- **验收范式冲突**：v1.20 的核心是以真实代码删除实现架构瘦身，退出依据是“存活不变量 100% 全绿”；而测试套件归一化的核心是**断言等价性证明（Parity Proof）**，不能将两个互不相关的风险源绑定在同一个回滚锚点上；
- **防止击穿护城河**：合并断言若采用短路布尔聚合（`assert not any(...)`），极易导致高危违规被无关风格违规掩蔽；`asset_inventory` 若粗暴 Mock，将导致 `--check` 失去对真实工作区（真实目录序、符号链接、去无序性）的真仓锚定；
- **独立里程碑价值**：v1.20 专注于轻量化生产系统；v1.21 专注于轻量化工程基础设施，边界分明。

## 第 2 章 核心不变量与验收制度（Parity Proof Protocol）

为杜绝测试重构引入“假绿”或“漏报”，v1.21 强制执行以下三条纪律：

| 不变量 | 规范要求 | 物理闭锁 |
|---|---|---|
| **TP-1 独立断言律** | 多个门禁合并到同一 AST 遍历时，**必须对每个不变量执行独立 assert**，严禁使用 `any()` 或 `all()` 短路聚合；每一个不变量必须配有专门的**对抗注入单测**（故意注入违规代码，断言门禁确凿报红）。 | `test_architecture_hygiene.py` + 负向用例 |
| **TP-2 真仓锚点律** | `test_asset_inventory.py` 允许将边界、容错、异常参数等用例迁移至虚拟临时工作区（Mock Workspace），但**必须永久保留至少 1 个完整的真实工作区端到端集成用例**，直接执行 `--check` 并强制挂接 Release/Tag 门禁。 | 真实工作区 hermetic 集成测试 |
| **TP-3 零净覆盖损失** | 归一化后的测试套件对生产代码的 AST 节点检查范围，必须是原有分散用例的超集或恒等集（$Scope_{merged} \ge \bigcup Scope_{isolated}$）。 | 门禁奇偶比对脚本 |

## 第 3 章 v1.21 任务规划与拓扑

```
step10 (v1.20 完工：分级执行与退役账本归一)
   │
   ▼
[v1.21 Milestone]
   ├── step21.1 P2  AST 架构卫生门禁归并 (TR-1 落地)
   │      │
   │      ▼
   ├── step21.2 P2  资产扫描测试单元化隔离与 I/O 去放大 (TR-2 落地)
   │      │
   │      ▼
   └── step21.3 P4  测试套件耗时基线冻结与 Tier-1 精准策展
```

### 3.1 step21.1 P2 — AST 架构卫生门禁归并 (TR-1)
- **目标**：将分散在 `test_lease_symbol_removal.py`、`test_touch_outcome_no_truthiness.py`（AST真值检查）、`test_no_api_bypass.py`、`test_no_vendor_literals_in_core.py` 中的重复源码遍历，归并为单次遍历的 `test_architecture_hygiene.py`。
- **纪律**：
  1. 遵照 TP-1，同一 AST 遍历下逐项独立断言；
  2. 交付针对被归并规则的对抗注入套件（Mutation Testing），证明单项违规能够准确击发对应错误信息。
- **收益**：全量回归减少 4~6 次全代码库 AST 重复 parse，削减约 8~12s 耗时。

### 3.2 step21.2 P2 — 资产扫描测试单元化隔离与 I/O 去放大 (TR-2)
- **目标**：重构 `test_asset_inventory.py`，将针对字典排序、前缀排除、异常处理、Markdown 格式化等纯逻辑断言改用轻量级临时目录 fixture（`tmp_path` 构造微型虚拟仓）；
- **纪律**：遵照 TP-2，保留 1 个不可跳过的完整端到端真仓 `--check` 集成测试。
- **收益**：`test_asset_inventory.py` 耗时由 >35s 降至 ≤5s，全量回归节约 30s 物理 I/O 等待。

### 3.3 step21.3 P4 — 测试套件耗时基线冻结与 Tier-1 精准策展
- **目标**：在全套去放大完成后，重新标定 Tier-1（≤ 5s）与 Tier-2（≤ 35s）耗时基线，固化自动化性能守卫。

## 第 4 章 退出判据 (Milestone DoD)

1. 全量回归测试（Tier-2）耗时从当前的 ~114s **降至 ≤ 40s**；
2. Tier-1 Fast Gate 耗时稳定保持在 **≤ 3s**；
3. 对抗注入单测 100% 覆盖全部合并的架构卫生门禁；
4. 九大核心不变量（INV-1 ~ INV-9）全量通过，零覆盖盲区。
