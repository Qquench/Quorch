## 第 1 章 核心宗旨与三方边界

### 1.1 背景与动因

在 v1.20 演进期间，为了确保架构去工业化（删除进程嗅探、后台心跳线程、配置兼容垫片等）不产生任何回归与漏报，各步骤引入了大量的重构期“防复现守门员”断言：
1. **AST 负向防复现门禁分散**：如 `test_lease_symbol_removal.py`、`test_prompt_layout_criterion.py`、`test_touch_outcome_no_truthiness.py` 中的 AST 语法树扫描，每个用例均独立启动全量源码 AST 解析；
2. **全仓静态扫描物理 I/O 放大**：`test_asset_inventory.py` 内部多次对真实工作区全仓进行遍历扫描、AST 提取与 Markdown 渲染，单文件耗时高达 35s+，占全量回归耗时逾 30%；
3. **测试维护认知负荷**：重构完成后，分散的脚手架测试与业务契约测试混杂，增加了长期演进的代码理解成本。

### 1.2 与 v1.20 的验收范式隔离

v1.20 的核心是以真实代码删除实现架构瘦身，退出依据是“存活不变量 100% 全绿”；  
v1.21 的基建部分核心是**断言等价性证明（Parity Proof）**与**只读取证**。  
两者回滚锚点不得共用。合并断言若采用 `any()/all()` 短路聚合，极易使高危违规被风格违规掩蔽；`asset_inventory` 若粗暴 Mock，将丧失真仓（真实目录序、符号链接、去无序性）锚定。

### 1.3 与 v1.22 的验收范式隔离（强制）

**禁止**在 v1.21 内引入任何真实生产代码删除动作。以下工作项**显式移交 v1.22**：

| 移交项 | 归属判据 |
|---|---|
| `G1'` 复杂度预算机械强制（MCP 工具三元组去重检测） | 需写入式检测语义改动 + 直接裁决生产拓扑 |
| `manifest_lease` 与 `workspace_lease` 双锁收敛 | 触碰 INV-1 唯一实现，须携 ★并发不变量硬门禁★ |
| `code_explorer` / `reporting` / `cli` 等模块切分或合并 | 真实生产代码删除，范式为存活不变量全绿 |
| 基于 step21.0 Emerged 候选的生产剪枝 | 授权顺序：证据（step21.0）→ 授权（v1.22）→ 删除（v1.22） |

> **裁决**：v1.21 = 证据与门禁的瘦身；v1.22 = 生产代码的瘦身。二者**物理隔离**。

### 1.4 冻结交互契约（继承）

`C2 心跳行契约` / `C3 Runner 完工交付卡契约` / `P4 过度工程驳回记录` —— 三者在 v1.21 内**状态不变、语义冻结**，直接继承 v1.20 §1.2。

## 第 2 章 核心不变量与验收制度（Parity Proof Protocol，TP-1 ~ TP-4）

| 不变量 | 规范要求 | 物理闭锁 |
|---|---|---|
| **TP-1 独立断言律** | 多个门禁合并到同一 AST 遍历时，必须对每个不变量执行独立 `assert`；严禁 `any()` / `all()` 短路聚合。每个不变量必须配备**对抗注入单测**（故意注入违规代码，断言确凿报红） | `test_architecture_hygiene.py` + 负向用例 |
| **TP-2 真仓锚点律** | 允许将边界/容错/异常参数用例迁至 `tmp_path` 虚拟工作区；但**必须永久保留 ≥ 1 个完整真实工作区端到端集成用例**，直接执行 `--check` 并强制挂接 Release/Tag 门禁，不可跳过、不可 quarantine | 真实工作区 hermetic 集成测试 |
| **TP-3 零净覆盖损失** | 归一化后测试套件对生产代码的 AST 节点检查范围必须是原有分散用例的超集或恒等集：`Scope_merged ⊇ ⋃ Scope_isolated`；须交付机械比对脚本 | 门禁奇偶比对脚本 (Parity Comparator) |
| **TP-4 再基线确定性律** | 资产清单再基线的产物与差异报告必须**逐字节可复现**；同一 commit 上连续两次运行的 `over_engineering_inventory.md` 与 Delta Report 必须**二进制一致**；且须在 step21.0 提交对上一版冻结快照的 SHA256 对比表 | `test_asset_inventory.py::test_rebaseline_determinism` |
