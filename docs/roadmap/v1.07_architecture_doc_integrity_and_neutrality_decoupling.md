## 1. 背景与演进契机 (Context & Motivation)

在顺利完成 Milestone v1.06（微内核观测自适应与任务目录双向互锁）后，系统全量测试套件达到 443 项全绿。然而，经过资深架构 Reviewer 引擎对当前全工具链与文档体系的综合红队诊断，暴露出以下三个亟待解决的结构性矛盾：

1. **架构文档与代码事实的“两张皮”漂移 (Documentation Drift)**：
   - 治理内核在 v1.05 与 v1.06 期间新增了 `observability_policy.py`、`manifest.py`、`reaper.py` 等关键模块，但在作为系统全局 SSOT 的 `docs/architecture.md` 中，部分核心模块完全缺失，且工具数量依然硬编码为“10/11 个”，缺乏机械化守卫门禁。
2. **“名义中立”背后的配置泄露与隐式厂商绑定 (Configuration Coupling Smells)**：
   - 虽然代码层消除了硬编码厂商字面量，但项目根目录 `.agents/quench_stack.yaml` 依然充斥着特定厂商的环境变量名称；更危险的是，缺少专用的 `.sample.yaml` 与 Git 忽略策略，存在真实开发者误将私有 Token 提交到公开代码库的安全隐患。
3. **外部执行器接入与双模型拓扑的“协同真空” (Handoff Disconnection)**：
   - 当开发者期望在纯本地环境（如 Codex CLI / Aider）使用低成本 API 执行任务，同时借助 IDE 内置的旗舰订阅模型进行审查时，缺乏机器可读、防篡改、轻量级的离线交接工件，导致双模型协作容易退化为混乱的人肉口头对齐。

## 4. 验收标准与关键不变量 (DoD & System Invariants)

1. **架构文档 100% 映射不变量**：服务端所有生产代码模块均在 `docs/architecture.md` 中有迹可循，静态扫描门禁零失败；
2. **明文密钥零泄露不变量**：任何直接在配置文件填入类似 `sk-` 明文密钥的行为，在启动时均被物理拦截报错并退出，`.gitignore` 必须覆盖本地私有配置；
3. **交接卡片签名防伪不变量**：降级生成的 Handoff Card 必须携带上下文 SHA-256 摘要，回填结论时验证一致性；
4. **全量测试回归基线**：全量 443+ 项自动化测试保持 100% 通过率。
