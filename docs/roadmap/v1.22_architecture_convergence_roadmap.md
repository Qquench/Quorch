## 第 3 章 关键设计契约（Design Contracts）

### 3.1 G1' 复杂度预算契约
- **输入**：step01 `ToolSurface` MCP 签名快照（step21.0 再基线版）。
- **检测（三条件）**：① 三元组 `(参数 schema + 状态跃迁 + 返回契约)` 去重；② 语义正交性；③ A1–A7 单机公理映射。
- **输出**：违规三元组 → 删除/合并候选，须经 Delta Report 证据授权方可执行。

### 3.2 双 lease 收敛契约（★高风险，携 INV-1 护城河）
- **语义域前置**：必须先证明 `manifest_lease`（任务所有权租约）与 `workspace_lease`（审查工作区变更互斥）的**语义域正交性**。
- **裁决分支**：
  - 若二者语义域**可**合并 → 物理合并，须证明 CAS 代际语义（`generation` / `owner_boot_nonce`）等价；
  - 若**不可**合并 → 裁决为"保留双 lease + 仅消除重复原语（`norm_path_pure` 等）"，**禁止**为删而合。
- **硬约束**：任何触及必须 ★并发不变量硬门禁★ 全绿 + C-1/C-2/C-6 不变量不回归；无法证明 CAS 语义等价则 **fail-closed 保留现状**。

### 3.3 模块切分/合并契约
- **前置**：import 图无环（step08 已保证，须复核）。
- **不变量边界**：`server.py` 保持 Tier-2 单一网关（A2）；`reviewer_engine.py` 保持唯一 provider egress（INV-9）；`assert_read_only_sandbox` 归口不变（INV-6）。
