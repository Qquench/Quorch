# 跨语言分区治理与防退化守卫架构规划
(Cross-Language Zoning Governance & Anti-Degradation Guards Roadmap)

> **状态**: 规划预研 (Planned / Future Roadmap)  
> **实施契机**: 面向多语言混合工程（TypeScript, Rust, Go, Python）与高并发工控场景的进阶边界守卫。  
> **核心定位**: 在双模型状态机与文件级白名单之上，构建**代码语义级分区约束**与**防 AI 无脑大段粘贴的退化守卫**。

---

## 1. 业务演进契机 (Motivation & Context)

随着被治理工程规模扩大与多语言混合架构的普及，仅依靠“文件路径白名单”仍存在以下深层痛点：
1. **单文件内部“退化性重构”**：AI 在修改白名单内的文件时，往往顺手精简或遗漏已有的关键防御逻辑、错误捕获分支或高精度类型断言。
2. **测试强度悄然缩水**：AI 为了让 DoD 快速变绿，可能下调断言阈值、注释掉难以修复的极限边界用例，形成虚假的“全绿”。
3. **无脑全量覆写（Paste Degradation）**：AI 倾向于全量生成并覆写数千行文件，抹除原有团队精心优化的并发锁与缓存逻辑。

---

## 2. 核心架构设计：四分区抽象与冻土叠加层 (Four-Zone Model & Frozen Overlay)

Quench 引入通用的四分区语义模型，配合各语言可插拔适配器：

```
┌──────────────────────────────────────────────────────────────┐
│                    Z-KERNEL (纯逻辑微内核)                   │
│   • 算法核心、核心状态机转移逻辑                              │
│   • 约束：允许重构，但错误分支数、边界断言数绝对值严禁净下降    │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│                   Z-CONTRACT (抽象契约层)                    │
│   • 公开 API、类型定义、接口协议、Protocol / Trait 声明       │
│   • 约束：签名破坏性变更必须提供配套契约测试凭证与升级任务      │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│                    Z-TEST (对抗性测试用例)                   │
│   • 单元测试、集成测试、模糊测试                              │
│   • 约束：允许新增与补充测试，严禁削弱已有断言强度与覆盖面    │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│                    Z-GLUE (环境与工程粘合)                   │
│   • 路由装配、配置读取、命令行参数接线                        │
│   • 约束：允许连线，禁止未受控的复杂业务逻辑在此膨胀          │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│                    ⊕ FROZEN (冻土叠加层)                      │
│   • 机器生成代码、依赖锁定文件、版本指纹                      │
│   • 约束：完全不可变，任何写操作直接触发物理 DENY             │
└──────────────────────────────────────────────────────────────┘
```

## 3. 可插拔适配器体系 (`LanguageZoningAdapter`)

通过通用抽象基类隔离不同语言的 AST / 词法分析实现：

1. **`PythonZoningAdapter`**：基于 Python 原生 `ast` 模块，精准审计函数复杂度、断言语句数量与异常捕获分支；
2. **`TypeScriptZoningAdapter`**：针对前端与 Node.js 技术栈，解析 `.d.ts` 与 TS AST，验证公开接口与导出契约；
3. **`GenericLexicalAdapter`**：基于行级启发式与括号/缩进深度分析的通用回退适配器，零外部依赖适配 Rust, Go, C++ 等任何系统语言。

---

## 4. 防退化守卫 (Runner-Side Paste Guard)

在 PreToolUse 钩子中集成 MinHash Jaccard 相似度与代码信号守恒检验：

- **大段无脑粘贴拦截**：检测大段新增代码与既有代码的结构亲和性，拦截未经本地消化的盲目粘贴；
- **全量覆写信号守恒比**：当模型尝试全量重写已有核心文件时，强制比对修改前后的核心符号密度与断言数量比值，低于安全阈值时自动拦截并要求说明理由。

---

## 5. 声明式配置 (`quench_stack.yaml`)

```yaml
quench_zoning:
  preset: "backend_standard"
  rules:
    - pattern: "src/core/**"
      zone: "Z-KERNEL"
      min_assertions_ratio: 1.0
    - pattern: "src/types/**"
      zone: "Z-CONTRACT"
    - pattern: "tests/**"
      zone: "Z-TEST"
      allow_assertion_decrease: false
    - pattern: "generated/**"
      zone: "FROZEN"
```

## 6. 分阶段落地路线图

- [ ] **Phase 1: 核抽象与适配器契约 (Z1)**：定义 `LanguageZoningAdapter` 抽象基类与通用结果数据结构；
- [ ] **Phase 2: 适配器实现与规则引擎 (Z2)**：实现 Python AST 适配器与通用词法回退适配器；
- [ ] **Phase 3: 防退化 Paste Guard (Z3)**：在 PreToolUse 钩子中实现断言守恒检验与覆写信号比防御；
- [ ] **Phase 4: 跨语言扩展与 TypeScript 支持 (Z4)**：支持 TypeScript AST 契约审计与常用项目 Presets。
